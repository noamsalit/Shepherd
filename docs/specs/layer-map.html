What may import what

Five layers, a composition root above them, and seven seams. Dependencies point down only. These are not conventions — the suite under tests/boundaries/ checks them as AST properties, not spellings, because a rule you can satisfy by renaming an import is not a rule.

The stack

L6root

daemons/

The composition root. Above everything, imported by nothing. Where the seams get their drivers and the wiring order is decided once. controld.py is 140 lines of 140 — the budget is asserted, because a root that grows logic becomes an undeclared layer.

may not

Nothing below L6 imports daemons/. A module that does has inverted the root: it can no longer be constructed without starting a process.

L5consume

master/web/cli/

Everything a human or the orchestrator agent uses. Three equal consumers, and none of them is special.

boundary 1

Consumer boundary (D19, D35). L5 reaches the system only through L4 — never L3, L2 or a store. test_master_isolation.py, test_consumer_boundary.py. It is an allow-list: a deny-list would pass the first import nobody thought to name.

L4gate

toolsurface/

The only place an action is authorized. The master, a tier-2 session over MCP, a queue write-back and a UI click all arrive at the same authorize() (D8, D32).

L3drive

orchestration/

Anything that acts on its own timer: queues, workers, reconcile, and the wake set (D31) — whose single drain site lives here.

L2observe

runner/engines/host/providers/signals/

Everything that reads or drives the outside world: engines, ptys, trackers, credentials, and the host itself. Six of the seven seams have their drivers here. Engine-specific vocabulary stays inside its adapter — if swapping the engine would edit signals/, the boundary has leaked.

L1persist

store/logs/core/

State, logs, and the shared vocabulary every layer above uses. core/ is capability-free — it holds types and constants, never a path to the outside world, which is why L5 may import it without a hole in boundary 1.

boundary 2

Storage boundary (D37). Nothing outside store/ imports a database driver. One writer, one rule set. test_storage_boundary.py.

↓ ↓ ↓

testkit/ is deliberately absent. It ships with the package but it is not a layer, so it is neither an importer nor a target.

Three rules that decide the shape

D36 — seam or module boundary?

A swap that happens at runtime gets a Protocol, a scripted double and a contract suite. A swap that happens at edit time gets a module boundary and an import test. That one line is why there are seven seams and why store/ is not one of them.

D56 — what a seam is for

Runner is a terminal seam; EngineAdapter is a CLI-harness seam. A harness-less API-loop engine is a third session class, not a Runner driver — implementing it there would mean a synthetic handle and a byte stream nobody typed: a driver that satisfies the type and lies about the world.

Why this is tested, not documented

The dominant defect class in this repo is checks that report success without checking — and it recurs inside checks written to close earlier instances of it. Every rule on this page has had a violation planted against it as an inert fixture, and went red.
