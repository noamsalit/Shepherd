   422	### 7.0 What `store/` may expose (D33)
   423	
   424	D26 refused a `Store` Protocol. That decision stands, but "no interface" is not
   425	"no contract" — a module boundary leaks exactly as easily as a bad Protocol if
   426	callers reach through it. Three rules, and each one is what makes the Mongo port
   427	in D2's remote path a rewrite of *one package* instead of a rewrite of its
   428	callers:
   429	
   430	1. **Expose verbs, not queries.** `claim_work_item(item_id, session_id, ttl_s)
   431	   -> bool`, never `query(sql, params)`. A verb can be implemented by another
   432	   engine; a SQL string cannot.
   433	2. **Return dataclasses, never driver rows.** The moment a caller touches
   434	   `row["status_class"]` or a `sqlite3.Row`, the engine has escaped the package.
   435	   `store/` converts at its own boundary and hands back `Session`, `WorkItem`,
   436	   `Repo`. This is §13's "never return a raw DB row" rule, applied one layer
   437	   earlier.
   438	3. **Transactions stay inside.** No caller writes `with store.transaction():`.
   439	   The atomic thing *is* one function — `claim_work_item()` is a conditional
   440	   `UPDATE` in SQLite and a `findOneAndUpdate` in Mongo, and the caller cannot
   441	   tell which.
   442	
   443	**The named trigger for promoting this to a `Store` Protocol: the day two
   444	engines must ship from one codebase** — a desktop `.pkg` on SQLite and a server
   445	deployment on something else. At that point drift between them is a real risk and
   446	one contract suite both must pass earns its keep. Until then the import rule is
   447	cheaper and less misleading. Following the three rules above makes that promotion
   448	mechanical rather than a redesign: a list of typed verbs with dataclass returns
   449	already *is* the Protocol, minus the `class` line.

   694	### Migrations
   695	
   696	Forward-only numbered SQL files in `store/migrations/`, applied in one
   697	transaction at `controld` startup.
   698	
   699	```sql
   700	CREATE TABLE schema_migration (
   701	  version INTEGER PRIMARY KEY, name TEXT NOT NULL,
   702	  checksum TEXT NOT NULL, applied_at TEXT NOT NULL);
   703	```
   704	
   705	Three rules, each guarding a failure that is hard to debug later:
   706	
   707	1. **Checksum mismatch on an applied migration → refuse to start.** History was
   708	   edited; guessing is worse than stopping.
   709	2. **Database version newer than the binary → refuse to start.** launchd will
   710	   happily run yesterday's binary after a failed upgrade, and old code reading a
   711	   new schema corrupts quietly.
   712	3. **`sessiond` never migrates.** It waits for `controld` to report the expected
   713	   version over the UDS. Two processes racing one migration is the bug you
   714	   cannot debug at 2am.

  1972	## 14. Testing
  1973	
  1974	Four lanes. The first two carry the value.
  1975	
  1976	1. **Classifier over golden fixtures.** A directory of **real stop-log records
  1977	   plus their transcript tails** — a rate limit, a crash mid-`Edit`, a
  1978	   permission prompt answered, a derailed completion, a `blocked_external`, a
  1979	   `stalled_pending_tool`. Pure function in, verdict out. **No mocking of Claude
  1980	   Code — the fixtures *are* Claude Code.** Adding a missed case is: capture signals, drop in a fixture,
  1981	   fix the rule, run `replay`.
  1982	2. **Contract suites, one per seam.** `WorkItemProvider`, `Runner`,
  1983	   `EngineAdapter` and `MasterRuntime` each get **one** test suite that every
  1984	   implementation must pass. A new provider is done when it passes the existing
  1985	   suite. This is the mechanism that stops the abstractions rotting into
  1986	   CCC's 400KB-per-engine shape.
  1987	
  1988	#### `Scripted*` — what they are and why every seam gets one
  1989	
  1990	**Every seam ships a `Scripted*` implementation**: `ScriptedRunner`,
  1991	`ScriptedWorkItemProvider`, `ScriptedEngine`, `ScriptedMaster`. They live in
  1992	`testkit/` and ship with the package, not only with the tests.
