## What changed in `src/`

- `orchestration/lifecycle.py` (ruling 10). `record_and_terminate` now reads the row **before**
  `runner.terminate` as well as after it. The killed verdict is written, and `KILL_WITHOUT_SESSION_END`
  bumped, when `ended_at` is the same across the kill (a missing row counts as `None` on either side).
  A finished turn's older `ended_at` no longer blocks the verdict. The module docstring keeps its order
  sentence, amended to "read the status and the row, write the record, *then* kill", and gains the
  ruling's definition. "leaves an already-ended row be" is amended to "leaves a row whose ending arrived
  during the kill be". No prose was removed. The file is 250 lines (cap 250). The only re-wrap is the
  `KILL_EVENT` publish call.
- `toolsurface/tools_messaging.py` (ruling 20, RD-5). `send` validates `body`, `origin` and
  `idempotency_key`, then checks `row.runner_handle is None` **before** `DELIVERY_LOCK` and
  `queue_message`. It returns `_refuse_no_pane(session_id)`:
  `{"message_id": None, "queued": False, "decision": "refuse_no_pty", "decision_text": refusal_text(REFUSE_NO_PTY), "reason": "<id>: no pane of ours — refused, nothing queued", "delivered": 0, "deferred": 0}`.
  `project_ask` gains `"from_fork_of_engine_session_id"`.
- `orchestration/ask.py` (ruling 21). `AskResult.from_fork_of_engine_session_id: str` is added.
  `from_fork_of = row.id`. The local `target_engine_id = row.engine_session_id` feeds `fork_argv`
  and `_residue` exactly as `from_fork_of` did before. The fork row is still parented on
  `session_id`. The early return: `from_fork_of` is `""` with no row and `row.id` for an unbound row,
  and the engine id is `""`. The mailbox path carries both.

## REM-FIX 1 (router, wf-20260927T110316Z-ee74fe07; code-reviewer + failure-hunter, cross-confirmed)

Six router decisions, taken under the owner's autonomy grant. They correct plan defects, so each is
also a **D-row follow-up for P13's ledger** (D74/D75 wording and ruling 10's reading). This section
supersedes the `ended_at`-changed reading written above under "What changed" and "Changed existing
assertions" (kept for history, not rewritten).

1. **(HIGH) Ruling 10 means a live session between turns.** `record_and_terminate` writes `killed`
   and bumps `KILL_WITHOUT_SESSION_END` only when (a) no session end arrived during the kill and
   (b) the row had no ending (`ended_at` None, or no row) **or** the pre-kill probe saw a live pane
   (`observed.alive`). A dead pane with an ending already recorded keeps its real verdict
   (`crashed`/`user_exited`) and nothing is counted.
2. **(MEDIUM) "A session end arrived during the kill" = the row's verdict changed** across the kill
   (`(stop_reason, decided_by)` before vs after), not `ended_at` moving. The liveness sweep
   (`signals/discovery_loop.py` `liveness_sweep`) stamps `ended_at` with no verdict, so a mid-turn kill
   racing the sweep still records `killed`. Known limit: a session end landing during the kill with the
   **same** `(stop_reason, decided_by)` as the previous turn's verdict reads as "no change" and is
   overwritten by `killed`; the kill was then still the session's end, so the verdict is not false.
3. **(HIGH) `ask()`'s `can_fork=False` fallback refuses a pane-less row** (`runner_handle is None`)
   with nothing queued: `method="mailbox"`, `text=None`, both ids set, and `refusal` =
   `refusal_text(REFUSE_NO_PTY)` + `"<id>: no pane of ours — can_fork is False and the question was
   refused, nothing queued"` (same family as `tools_messaging._refuse_no_pane`).
4. **(MEDIUM) The early-return ids are pinned**, one test per branch: no row gives `("", "")`, and an
   unbound row gives `(row.id, "")`.
5. **(LOW) `send_to_session`'s tool description** now says a send to a pane-less session is refused
   with nothing queued. **For P13 doc-sync (not edited, `web/` is out of scope):**
   `src/shepherd/web/static/session.js:45-47` still says "a session killed after a turn keeps that
   turn's `stop_reason`". That is stale since ruling 10.
6. **(MEDIUM) Sibling, no migration now:** rows queued **before** D74 to a pane-less session stay
   pending in `mailbox_message`, waiting for a delivery trigger that never comes. The send path no
   longer creates them, but existing ones are not swept. This also covers the ask fallback's pre-fix
   rows. Record it in P13's ledger.
