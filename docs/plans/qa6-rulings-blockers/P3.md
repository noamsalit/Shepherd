## Deviations

- **Text formats (decided, low blast radius).** The event line reads `turn ended · <outcome>` and
  `rate limit · <status>`, with `—` for a missing datum (principle 5). A stopping rate limit's
  thread line is the same string. The plan gave `turn ended · finished` only as an example.
- **The merged step keeps the call's argument keys.** The step body is `arguments: <keys>` (or
  `(no arguments)`), then a newline, then the result text. `.step-body` is `white-space: pre`. I
  chose one text body over a second `.step-body` element, because U26 reads `.step-body` with
  Playwright's strict `text_content()`, and a second element would make that ambiguous. It also
  needs no new CSS class.
- **A second result for an already-answered id** renders as its own step rather than
  overwriting the first. That keeps "nothing is dropped".
- **The `error` ending is unchanged.** It still enters the thread through `eventText`. Ruling 4
  names the final `result` text on `turn_ended` only.
- Plan text I treated as stale, per the router: P3 Objective `:999` and RD-4 `:420` say
  `#shepherd-status`. Events go to `#shepherd-event`.
- Test name: the plan's `test_an_event_fills_an_empty_status_slot` is rev 3's. Under rev 4 I named
  it `test_an_event_fills_an_empty_status_area`: the event line shows the text and the status slot
  stays empty.

### What changed

1. **(HIGH, plan defect) Ruling 4 covers every SDK ending, not only `turn_ended`.** This
   supersedes the earlier deviation "the `error` ending is unchanged". `onMasterEvent` now sends
   `error` through the same ending handler, `turnEnded(kind, data)`. The event line reads
   `turn ended · error`. The turn's `lastText` entry is deleted. In the thread:
   - if the text is new, it renders as prose;
   - if the text equals the turn's last text (true in every probe capture, since
     `projection.py` sets `text=obj.result`), or there is no text, the word `error` renders
     instead, so the thread still says the turn failed.

   The exception-path `error` from `master_turn.py:303` takes the same path. Its text is new,
   so it renders.
2. **The event line is cleared on send.** `submit()` runs `fill("shepherd-event", "")` right after
   `youSays(text)` and **before** `await post(...)`, because a fast `turn_ended` can arrive before
   the POST answers. `fill` is a call, not an assignment, so `REQUIRED_SHEPHERD_ASSIGNMENTS` is
   unchanged. The six `#shepherd-status` writers are unchanged (`git diff -U0` has 0
   `shepherd-status` lines). They now sit at `:149 :154 :168 :173 :470 :515`.
3. **A failed tool result is marked.** `stepBody(TOOL_RESULT, …)` prefixes `error · ` when
   `detail.is_error === true`. This applies to a merged step and to a result's own step. There is
   no new CSS.
4. **U26 `ui.prose_and_step_before_turn_ended` now has its own ordering signal (kept, not
   retired).** This is my choice. Nothing is added to P15's list of vanished clauses. A new
   `AT_TURN_END` MutationObserver is installed on `#shepherd-event` before the send. It snapshots
   the Shepherd side of the thread the first time the line reads `turn ended…`. The clause passes
   when the snapshot's tail is `["prose:QA6 U26 prose", "step:fleet_summary"]`. That is what the
   thread held when the ending was shown. A step or prose line added after the ending fails it.
5. **L1 `ui.assistant_grows_in_two_updates` checks for the step.** It is still one clause with
   the same name. When `"fleet_summary" in turn.tool_names()`, one of `this_turn`'s additions must
   also have text containing `fleet_summary`. `THREAD_OBSERVER` records `node.textContent`, and a
   step turn's text includes its `.step-tool`.
6. **U26 `ui.no_turn_ended_line_in_the_thread`** also rejects any prose containing the event
   line's text, `turn ended ·`.
7. **Open steps are dropped at turn end.** A `state.steps` entry is now `{content, turnId}`.
   `closeSteps(turnId)` runs in the ending handler (for both `turn_ended` and `error`). A result
   that arrives after its turn ended therefore renders as its own step, so it is still not
   dropped. I named the field `content`, not `body`, because `test_the_response_envelope_…`'s
   `field_reads(chat.js, "body")` read `open.body.append` as a response-envelope field. It was
   briefly red on that name, and I renamed it.
