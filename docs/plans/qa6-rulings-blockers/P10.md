## Design notes

- `toolsurface/rpc.py` (209 lines): ADR-QR-1 as written. `answer_request` never raises; refusals are
  `{"ok": false, "failure": "refused", "error": "bad request (correlation_id=<sent or minted>)"}`;
  unencodable data → `failed` / `not transportable`. It logs nothing and never prints.
  `call_remote`: `FileNotFoundError`/`ConnectionRefusedError` on connect → `None`; every later failure →
  `FAILED`, `the daemon did not answer: <class>`.
- `daemons/control_rpc.py` (61 lines, ≤ 150): wiring only; `finally` closes, `unlink_owned_socket`,
  then `release_claim` (D72). It re-exports `RPC_SOCKET_NAME`, which `controld` imports from it.
- `controld.py` 140 → 140 (net zero, prose kept and re-flowed; ≤ 140). Both plans are claimed before
  the port bind; four threads `("ingest", "rpc", "scan", "http")`; `start()` waits for both bounds;
  `Controld.rpc_socket_path`. `controld.main`'s arms are P8's: `SocketInUse`/`ClaimFailed` (either
  socket) are named, "port N is not available" stays on the `OSError` arm around `create_server`.
- `cli/commands.py`: `Cli.remote: Path | None = None` (defaulted, so no `Cli(` caller moved);
  `Cli.call` → `call_remote` when `remote` is set and answers, else local `invoke`. `explain()` unchanged.
- `cli/main.py`: `remote=rpc_socket(host)` (`SocketPathTooLong` → `None`); `since_problem()` refuses a
  `--since` that `core.clock.parse_date` rejects, **after** `parse()` and before any call, printing the
  one sentence with no usage text (C5 does not list `invalid_since_date` in `PARSE_ERRORS`, and the
  phase requires stderr to be exactly that line). The module docstring cites D68.

## Deviations

1. **`src/shepherd/engines/claude_code/ingest_socket.py` edited** (not in P10's file list; direct
   breakage caused by this phase). `_umask` is process-global save/set/restore; with the `ingest` and
   `rpc` listeners binding on two threads at once, the pairs interleaved and restored the socket's
   `0o177` as the process umask, after which every directory the process made was `0600` and could not
   be entered. Fixed by serialising the window with a module lock `_UMASK_GUARD`; pinned by
   `test_two_listeners_binding_at_once_leave_the_process_umask_alone` (RED `0o177`). Other threads
   creating files during a bind window still see the socket umask for that instant — pre-existing
   since M1, unchanged.
2. `--since` validation lives in `main()` (`since_problem`, right after `parse()`), not inside
   `parse()`, so the refusal prints one sentence without the usage block (the phase's exact-stderr
   requirement), and it uses `core.clock.parse_date` rather than `re` + `date.fromisoformat`:
   `test_one_clock.py::test_only_core_clock_reads_the_wall_clock` forbids `fromisoformat` outside
   `core.clock`, and `parse_date` is already the strict ASCII + calendar reader the replay tool uses.
3. `answer_request` refuses a request over `MAX_REQUEST_BYTES` after `read_to_eof` has read it whole
   (the shared reader is unbounded; its 1 s idle timeout still bounds a stalled peer). A bounded read
   would be an `ingest_socket` API change; left for a later phase.
4. If the `rpc` claim is refused after the control claim succeeded, the control claim stays held
   until the process exits — the same as P8's behaviour for a busy port, and `controld.main` exits.
