## What was built

- `core/anomalies.py`: `MASTER_FAILED = "master_failed"`, appended after M4's section under the
  comment `post-M4 (qa6 rulings, D79)`.
- `orchestration/master_turn.py`: `TurnDriver(..., record_failure: Callable[[str, str], None])`,
  keyword-only and required. `wake_turn() -> TurnStarted | None` claims the slot or returns `None`
  (busy, nothing drained). It builds the runtime, then drains, and opens with
  `render_wake_text(drain(...))` alone. An empty drain closes the runtime, frees the slot and
  returns `None`. Both failure paths (a failed open in `send_turn` or `wake_turn`, and a raise inside
  `_run_turn`) call `record_failure(turn_id, type(error).__name__)`. The mid-run call comes before
  the release, so a caller woken by the end of the turn reads the count. `send_turn` and `wake_turn`
  share `_claim`, `_start`, `_fail_open` and `_abandon`, and `send_turn`'s behaviour is unchanged.
  `_abandon` holds the REMFIX-1 close-then-release-in-`finally` shape.
- `orchestration/wake.py`: `WAKE_LEVEL = 3` and
  `LevelThreeWaker(store, *, level, open_wake, bump)` with `tick() -> bool`. RD-3 is
  `store.retry_chain_depth(id) < MAX_MASTER_ATTEMPTS`. A capped item is bumped as
  `wake_retry_cap_reached` once per session (the public `declined: set[str]`) and left in the set.
  `needs_you` and `refused` are excluded by `wake_candidates` (the store's sentence), not here.
- `toolsurface/registry.py`: `audit_master_failure(turn_id, error_class)` builds the one
  `AuditRecord` beside `_audit`. `tool` and `blast_class` are read off the registered
  `master_send` `ToolDef`, so the value is the tool's own and not a second spelling. It is a no-op
  with no chokepoint, and also a no-op in a process with no `master_send` registered.
  `MASTER_TURN_TOOL = "master_send"`. `MASTER_ACTOR_ID = "master"` is the value of
  `daemons/plane.py::MASTER_CALLER_ID`, which L4 cannot import. D71 "binds" → "serves" in all three
  places: the module docstring, the `RegistryFrozen` text, and `freeze_registry`'s docstring.
  `grep -rn "server bound" tests` had no hit, so no test changed with it.
- `toolsurface/compose.py`: `record_failure=_master_failure_recorder(store)` (a named factory:
  `_bump(store, AnomalyKind.MASTER_FAILED)` then `audit_master_failure`).
  `LevelThreeWaker(store, level=lambda: int(autonomy_level(store)), open_wake=driver.wake_turn,
  bump=store.bump_anomaly)`. `sweep=sweep_and_wake(mailbox_sweep(store, runner), waker.tick)`,
  which returns the mailbox counts unchanged, adds no thread, and is new in `__all__`. The

## Deviations

1. `LevelThreeWaker`'s `level`, `open_wake` and `bump` are keyword-only. The plan's compose line
   already passes them by keyword.
2. `audit_master_failure` is also a no-op when `master_send` is not registered. The ADR says only
   "no chokepoint". The blast class is read off the tool rather than restated, so without the tool
   there is no honest value to write. In production, `master_send` is registered before the
   chokepoint is installed, in the same composition.
3. `compose.py`'s waker call is two lines with the continuation aligned under the open parenthesis,
   and the two small closures have no blank line before their `return`. Both keep the file at 599
   lines (cap 600).
4. `tests/toolsurface/test_tools_master.py`'s summary budget (above) is one file outside the plan's
   list.

## Siblings left open

- A capped item stays in the wake set until the next user turn (RD-3's level-2 behaviour). The
  waker's `declined` set lives for the life of the process, so after a restart the same capped
  session is counted once more. That is once per session per process, never once per pass.
- A wake turn claims the slot, so a user's `master_send` that arrives during a wake turn is refused
  "already running", the same as behind any other turn (RD7).
