## Deviations

1. **The trust successor uses an empty throwaway config home, not `engine_config_home=None`.**
   `None` falls back to the user's real `~/.claude.json` (`trust.config_file`). Whether that file
   names the tmp directory is a fact about the host, not the test. The empty home gives the same
   unknown (`trusted is None`, `trust_source` `absent: …`) deterministically, and it reads no host
   file. The test also asserts through `trust_state(...)` that the reader still says `None`.
2. **`index_spec` in `test_migration_005.py` compares more than the 003 test's does.** It also
   checks `partial` and the stored index SQL, so a recreated `ux_session_engine_id` that lost its
   `WHERE` clause would go red.
3. **The negative control's text is derived from 005 itself.** Every `;`-separated statement whose
   non-comment text mentions `mailbox` is dropped. That keeps the control from drifting from the
   migration it controls. It is inert SQL in `tmp_path`, and it asserts both that the stash really
   is gone from it and that `session_new` is still there.
4. **`test_a_v5_database_refuses_a_v4_binary_by_rule_2`** simulates "a v4 binary" by
   monkeypatching `migrate.EXPECTED_SCHEMA_VERSION` to 4 and pointing at the 001–004 directory,
   the migrate reader's own rule-2 path. No second binary is built.
