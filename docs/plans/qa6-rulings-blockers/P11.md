## What changed

- `src/shepherd/web/static/session.js` (decision card only):
  - `PERMISSION_ANSWERS = { 1: "approve", 2: "approve_always", 3: "deny" }`, with a comment citing
    `dialog_keys.PERMISSION_KEYS`. `UNIVERSAL_ANSWERS = { approve: "approve", reject: "deny" }`.
  - `answerFor(kind, universal, choice)`: a word only when `pane_kind === "permission_dialog"`,
    keyed by number (readable) or by label (the two universal options). `Object.hasOwn`, so no
    prototype member is an answer.
  - `choiceRow(choice, answer)`: an answerable choice is a `<button type="button" class="choice">`,
    and an inert one is `div.choice.choice-inert`, as before. The container is now
    `div.choices`, not `ul`, because a `<button>` is not a list item. No new class, so `app.css`
    is untouched.
  - `answerChoice(card, outcome, sessionId, answer)`: exactly one `POST
    /api/sessions/{id}/permission` with `{"choice": answer}`. Two guards:
    - every choice on the card is disabled while the answer is out;
    - `answering` (a `Set` of session ids, the `renaming` pattern) refuses a second POST from a
      card re-opened while the first is still out.
    The reply paints only if the card is still connected (BC-12). `renderDecision` replaces the
    card on every open, so a disconnected card means the pane has moved past it. The outcome goes
    into a `role="status"` note: `answered: <word>` (`decision-done`), `not answered: <reason>`,
    `could not answer: <error> (<correlation_id>)`, or unreachable (all `decision-readonly`). An
    answered dialog keeps its choices disabled. Any other result enables them again.
  - `DECISION_INERT` is still shown for `trust_dialog` and for any choice with no mapping. Its text
    is now "answering this screen from Shepherd is not built in this build — press the option in
    the session's own terminal." It used to say "answering from Shepherd", which is no longer
    true for the permission dialog.
- `tests/web/test_decision_answer_table.py` (new): parses both JS tables and compares them to
  `{n: k for n, k in zip((1, 2, 3), PERMISSION_KEYS)}` and to the literal.
- `tests/web/test_decision_live.py`:
  - six new browser tests (below);
  - the `pane` fixture now honours `indirect` parametrization, like `test_routes_decision.py`'s;
  - the `scripted_runner` fixture takes an optional tuple of panes for the reads after the card's.
- `tests/web/test_session_wiring.py::REQUIRED_ASSIGNMENTS`: 13 new assignments, each with a
  comment. The whole-set equality is green.

### What changed

- `src/shepherd/orchestration/dialog_digest.py` (new, pure): `digest_of(text) -> str | None`.
  It is the sha256 hex of the dialog text's UTF-8 bytes, exactly as the pane gave it, or `None`
  when there is no dialog. `DIALOG_CHANGED` is the refusal text. The module has two callers, one
  on each side of the wire, so they cannot drift apart.
- `toolsurface/tools_terminal.py::get_decision` (the tool behind `DECISION_PATH`, registered in
  `tools_m3.py`): the reply now carries `dialog_sha256`, computed by the server over
  `state.dialog_text`. The digest covers the whole dialog text, not only the parsed `prompt.text`.
  That is stricter: a cursor move also changes it and gives a false refusal. That result is
  fail-closed, and a second click on the repainted card sends the answer.
- `orchestration/dialogs.py::answer_permission(..., dialog_sha256: str | None = None)`. When a
  digest is given, the function checks it only after the pane kind, the sidecar and the option
  set have passed. It recomputes the digest over the pane it just re-read. If the digests differ,
  it refuses with `"{session_id}: the dialog changed since it was shown — nothing was sent; read
  it again before answering"` and sends no key. **Omitted, the gate is unchanged.** That is the
  master's MCP path (`answer_permission` tool with no digest). Binding the master to a read is
  **out of scope** for this fix and is recorded here as a sibling left open.
- `tools_m3.py::answer` / the `answer_permission` tool schema: optional `dialog_sha256` string,
  passed through. The `tools_terminal` import was split over two lines. No names changed.
- `web/routes.py::BODY_ARGS["/api/sessions/{session_id}/permission"]` is now `("choice",
  "dialog_sha256")`.
- `web/static/session.js`:
  - `answerChoice(row, card, outcome, answer, digest)` posts `{choice, dialog_sha256}` using the
    digest the card was built from.
  - On any result other than "answered", **the clicked card is never enabled again**. If the
    session is still on screen, `renderDecision(row)` repaints it from a fresh read, and
    `paintCurrent` puts the reason on the new card. If the fresh read shows no dialog, the reason
    is added below the "no dialog" note.
  - `paintCurrent(sessionId, text, done)` replaces the `isConnected` check (BC-12 R3, the
    `commitRename` rule). A reply paints only while `showing === sessionId`, and it paints into
    the card that is up now.
  - In flight: if a card is re-opened while its session's answer is still out, it shows
    `ANSWER_PENDING = "an answer for this session is still out"` with its choices disabled. A
    click on it paints that line and posts nothing. When the reply lands, it is painted into this
    card.
  - The `role="status"` note is in the tree from the first paint. It is never toggled with
    `hidden`, and its class is `decision-status`.
- `web/static/app.css`: added `.choice[disabled]` (greyed, `not-allowed`, and a hover that offers
  nothing) and `.decision-status { margin: 0; }`. The stale comment at `:1578-1580` ("nothing on
  any page posts to …/permission") is rewritten: an inert choice is a trust row or a permission
  choice with no answer word (D77). **app.css is declared for P13** (see below).
