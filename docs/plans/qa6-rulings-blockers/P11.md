## What changed

- `src/shepherd/web/static/session.js` (decision card only):
  - `PERMISSION_ANSWERS = { 1: "approve", 2: "approve_always", 3: "deny" }`, with a comment citing
    `dialog_keys.PERMISSION_KEYS`. `UNIVERSAL_ANSWERS = { approve: "approve", reject: "deny" }`.
  - `answerFor(kind, universal, choice)`: a word only when `pane_kind === "permission_dialog"`,
    keyed by number (readable) or by label (the two universal options). `Object.hasOwn`, so no
    prototype member is an answer.
  - `choiceRow(choice, answer)`: an answerable choice is a `<button type="button" class="choice">`,
    and an inert one is `div.choice.choice-inert`, as before. The container is now
    `div.choices`, not `ul`, because a `<button>` is not a list item. No new class, so `app.css`
    is untouched.
  - `answerChoice(card, outcome, sessionId, answer)`: exactly one `POST
    /api/sessions/{id}/permission` with `{"choice": answer}`. Two guards:
    - every choice on the card is disabled while the answer is out;
    - `answering` (a `Set` of session ids, the `renaming` pattern) refuses a second POST from a
      card re-opened while the first is still out.
    The reply paints only if the card is still connected (BC-12). `renderDecision` replaces the
    card on every open, so a disconnected card means the pane has moved past it. The outcome goes
    into a `role="status"` note: `answered: <word>` (`decision-done`), `not answered: <reason>`,
    `could not answer: <error> (<correlation_id>)`, or unreachable (all `decision-readonly`). An
    answered dialog keeps its choices disabled. Any other result enables them again.
  - `DECISION_INERT` is still shown for `trust_dialog` and for any choice with no mapping. Its text
    is now "answering this screen from Shepherd is not built in this build — press the option in
    the session's own terminal." It used to say "answering from Shepherd", which is no longer
    true for the permission dialog.
- `tests/web/test_decision_answer_table.py` (new): parses both JS tables and compares them to
  `{n: k for n, k in zip((1, 2, 3), PERMISSION_KEYS)}` and to the literal.
- `tests/web/test_decision_live.py`:
  - six new browser tests (below);
  - the `pane` fixture now honours `indirect` parametrization, like `test_routes_decision.py`'s;
  - the `scripted_runner` fixture takes an optional tuple of panes for the reads after the card's.
- `tests/web/test_session_wiring.py::REQUIRED_ASSIGNMENTS`: 13 new assignments, each with a
  comment. The whole-set equality is green.

## New tests (browser, over the shipped server, scripted runner, frozen captures)

- `test_clicking_a_permission_choice_posts_its_answer_once`: choice 2 sends one POST
  `{"choice": "approve_always"}`. The runner is handed `[b"2"]`, and the card shows `answered`.
- `test_a_double_click_posts_once` (**PP12**): a double-click on choice 3 sends exactly one POST
  `{"choice": "deny"}`, and the runner is handed `[b"3"]`.
- `test_the_trust_dialog_choices_stay_inert_and_say_why`: no `<button>`, `No, exit` and the inert
  reason are on the card, and a click sends no POST and no write.
- `test_an_unreadable_permission_screen_answers_approve_and_reject_through_the_same_route[approve|reject]`:
  on the `_unparseable()` pane, two unnumbered buttons. `approve` sends `{"choice":"approve"}`,
  `reject` sends `{"choice":"deny"}`, and an outcome is shown.
- `test_a_refused_answer_is_shown_on_the_card`: the panes are (permission, `03-after-stop`). The
  server refuses with `…not a permission dialog`, the card shows that text, no key is written,
  and the choices are enabled again.
- `test_a_reply_for_a_card_no_longer_open_paints_nothing` (BC-12 + PP12 across cards): the POST
  is held with `page.route` and the session is re-opened by its Flock card, not by a reload. A
  click on the new card sends nothing. After the reply is released, the new card shows no outcome
  and its choices are enabled.
