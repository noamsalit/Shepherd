## What changed

- `src/shepherd/web/ws.py`: `pump_input(read: Callable[[int], bytes], deliver: Callable[[bytes],
  None]) -> int`, plus `READ_BYTES = 1 << 16`. It reads with `read(READ_BYTES)` and parses with
  `parse_frame`. Text, binary and continuation payloads go to `deliver` verbatim, with no decode.
  Ping and pong are dropped. A close frame or an empty read returns `CLOSE_NORMAL`. A parser
  refusal returns its code: 1002 for an unmasked or reserved frame, 1009 for a frame over
  `MAX_FRAME_BYTES` (refused from the header, before its payload is read). The module docstring
  no longer says the server "never reads". It names `pump_input` as the one caller of
  `parse_frame` (D76).
- `src/shepherd/toolsurface/tools_terminal.py`: `TerminalStream` gains the field
  `writer: Callable[[bytes], None]` and `write(data: bytes) -> None`. `terminal_stream()` binds
  `writer` to `runner.write(handle, data)` for the handle it just resolved, so input can only
  reach the session the audited open was for. `write` catches `RunnerRefusal` (the pane is gone)
  and closes the stream. That ends `chunks()`, so the server sends its close frame; keys are not
  dropped silently. The file is **450 lines**, exactly the cap. To fit, I made the import block
  contiguous, removed the inaccurate `# ----- the four handlers` header (the section has six
  handlers), and shortened `kill_landed`'s placement paragraph to two lines. Its reasoning is
  still in full in `test_tools_m3.py::test_kill_landed_reads_both_answers_the_kill_path_gives`.
- `src/shepherd/web/server.py` `_terminal`: the origin check, the handshake, the audited
  `invoke("terminal_stream")` and the snapshot frame are unchanged and still come first. After the
  snapshot flush, `_terminal` starts one daemon thread (`INPUT_THREAD_NAME =
  "shepherd-terminal-input"`) that runs `_read_keys`. `_read_keys` calls
  `ws.pump_input(self.rfile.read1, ending.stream.write)`. `_Ending` holds the reader's close code
  and does the **single** `stream.close()` under a lock. Either thread can end the connection, and
  `test_ws.py::test_live_chunks_arrive_in_order_and_stop_on_close` pins `closes == 1`. The writer
  loop is unchanged, except that its close frame now carries `ending.code` (1000 normally, 1009 or
  1002 when the reader refused a frame). `finally`: `ending.close()`, then `_stop_reading`, which
  calls `connection.shutdown(SHUT_RDWR)` so a reader blocked on a silent client returns, then does
  a bounded `join(INPUT_JOIN_S = 5.0)`. New imports: `socket`, `threading`.
- `src/shepherd/web/static/terminal.js`:
  - `disableStdin: false`
  - `term.onData((keys) => sendKeys(socket, keys))`. `sendKeys` sends only while
    `socket.readyState === WebSocket.OPEN`.
  - on `onclose` (not user-initiated), `stopInput` sets `term.options.disableStdin = true` and
    shows `INPUT_CLOSED` beside the stream notice. That is the "input is impossible, and why"
    state.
  - `INPUT_UNAVAILABLE` is removed. `INPUT_CLOSED` is a different, true sentence for a different
    state. The head comment records D76 and the reversal of T19-c.
  - No HTML sink. Typed text reaches only `socket.send`. `snapshotForEmulator` is untouched, so
    the P15 terminal-view safety scan note still holds.
- `src/shepherd/web/static/session.js`: the import drops `INPUT_UNAVAILABLE`, and
  `note.textContent = FIT_LIMITATION`. The comment says why.
- `src/shepherd/web/static/vendor/VERSION.txt` (not in the plan; see Deviations): the G-M3-6
  paragraph cited the retired test and said `terminal.js` ships `disableStdin: true`. It now
  records T19-c's history and D76, cites the new proofs, and still says vendoring proves none of

## Security properties (as asked)

- Input goes only to the session the socket was opened for. The writer is bound in
  `terminal_stream()` to the handle `handle_for` resolved for that session, and is never looked up
  per frame. An attached row has no handle, so the open is 404 and no reader starts
  (`test_an_attached_session_gets_no_reader`). A bad origin gets 403, with no stream, no reader and
  no write (`test_a_bad_origin_gets_no_reader`).
- Frames are size-bounded: `MAX_FRAME_BYTES` (1 MiB) is refused from the header with 1009, and
  one read is `READ_BYTES` (64 KiB).
- No shell interpretation: the bytes go to `Runner.write`, which is `LocalRunner`'s
  `send-keys -H <hex>…` argv (byte-exact; every tmux call goes through `_run` with `-L`). There is
  no `shell=True` and no `-l` string path. This is the existing literal write path, and nothing
  here builds an argv.
- No audit row per keystroke (PP11): `test_typing_writes_no_audit_row_but_the_open_does` checks
  that the sink holds exactly one `terminal_stream` record, whose args are `{session_id}`.
