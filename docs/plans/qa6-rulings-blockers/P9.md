## REM-FIX 1 (review: code-reviewer + failure-hunter, cross-confirmed)

Router decision (owner autonomy grant): fix the BC-32 body read here in P9. `web/server.py` is
already a declared edit for this phase set, so this adds no new surface.

- **Finding (MEDIUM).** `settimeout(BODY_READ_TIMEOUT_S)` around `rfile.read(length)` is an idle
  window per `recv`, not a deadline for the whole body. A probe showed 11 bytes sent at 1 B/s
  accepted after 11.1 s, against a 2.0 s window.
- **Fix.** `_read_body` sets `deadline = time.monotonic() + BODY_READ_TIMEOUT_S`. A new
  `_read_until(length, deadline)` reads with `rfile.read1` until it has `length` bytes. Each pass
  re-arms `settimeout` to what is left, and the loop stops at EOF, on an `OSError` (a timeout is
  one) or at the deadline. The rest is unchanged: `finally: settimeout(None)`,
  `close_connection = True` on a short body, and the generic 400 with no exception text. The
  docstring and the `BODY_READ_TIMEOUT_S` comment now say "whole-body deadline". Using `read1`
  also returns any body bytes the header parse already buffered.
- **Quick win (LOW, done).** The short-body 400 now carries `Connection: close`. `_send` already
  took `headers`. `_send_json` and `_fail` each gained one optional `headers` argument that they
  pass on, and every other caller is unchanged. `do_POST` sends the header only when
  `close_connection` is already set.
- **Tests** (`tests/web/test_server_short_body.py`):
  - new `test_a_trickled_body_is_a_400_once_the_window_has_passed`: 100 declared bytes, 1 byte
    every 0.25 s from a sender thread. It must get a 400 with
    `BODY_READ_TIMEOUT_S <= elapsed < ANSWER_WITHIN_S`.
  - new `test_a_short_body_on_a_keep_alive_connection_is_a_400_then_closed`: no
    `Connection: close`. It asserts the 400, the `Connection: close` response header and the
    generic envelope, that `recv()` then reaches `b""`, and that captured stderr is `""`.
  - `_head` gained `close: bool = True`. The existing short-body and slow-but-complete tests are
    unchanged and still pass.
- **RED 1** `pytest -p no:randomly tests/web/test_server_short_body.py` → `1 failed, 4 passed`:
  `test_a_trickled_body_is_a_400_once_the_window_has_passed` →
  `AssertionError: b''` (no status line within the test's 3.0 s: the per-`recv` window never
  fired). The keep-alive variant passed on the old code: it pins the close behaviour.
- **RED 2** (the header): with the header assertion added → `1 failed, 4 passed`,

import-set gate records stdlib imports too. So
`test_the_consumer_import_sets_are_additive_only` now fails with
`undeclared: ['web/server.py: time']`. That is a **known red added by this REM-FIX, until P13**.
The brief says only P13 may edit the post-M4 import table, so I did not declare it here.

calls, which is not a deadline.

## Siblings left open

- **The header phase of a request has no timeout. It was already like this before P9.** A client
  that sends a partial request line or headers and then stalls still holds a handler thread in
  `BaseHTTPRequestHandler`'s `readline`. BC-32 was only about the body. The fix would be the
  class-level `timeout` of `StreamRequestHandler`, but that would also apply to the long-lived SSE
  and WebSocket connections. It needs its own ruling.
