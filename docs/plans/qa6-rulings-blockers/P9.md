## Deviations

1. **P10.md resolution.** The plan says to "append the branch's Router decision / BC-32 section".
   That section is on mainline, and the branch never had it. I kept the mainline file as it is and
   appended the ruling-11 merge note. Nothing was lost: the branch side is a prefix of mainline.
2. **One extra positive control**, `test_a_declared_server_edit_with_its_live_digest_is_accepted`.
   The two negative controls the plan names both pass under the old rule, because the old rule
   rejects everything. So they cannot give the RED the plan asks for ("the old test rejects any
   declared edit"). This control is that RED.

   table as a parameter, so the controls can drive it with literals, and it flattens the table
   with the same `flattened` that `declared_additions()` uses. The live test passes
   `POST_M4_ADDED_IMPORTS`. The rule is the one the plan states:
   `added == declared_additions() + post-M4 additions`.
4. **The merge is a commit in the phase branch** (`4d82b68`), as the router's prompt allows. The
   boundary-test edit, this ledger and nothing else are left uncommitted for the router.
