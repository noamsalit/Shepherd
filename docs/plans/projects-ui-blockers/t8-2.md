## What the tool answers, and why it is three booleans

`get_decision(store, runner, session_id)` — `LOCAL_READ`, `HUMAN` only. It
composes T8.1's pure `read_decision` over one `runner.pane(...)` observation.
There is no write on the path at all, and that is the safety property rather
than a style note: on the trust screen the key that looks safe is the one that
exits the session.

| field | what it says | why the page cannot infer it from the others |
|---|---|---|
| `ok` | there was a pane of ours | `no_pane(...)` otherwise — every attached session |
| `asking` | the pane is a dialog kind | an idle session is asking nothing (E20) |
| `readable` | `read_decision` produced a prompt | a degraded screen still has an ask (E16) |

`text` is the parsed ask when `readable`, and the **whole screen verbatim** when
not: once the parser has refused to say which line is the ask, choosing one here
would be the same guess made one layer up. `choices` is empty in that case, and
the card supplies `approve`/`reject` **unnumbered** — a number is a key the
engine drew, and these two are not.

## The three degradations, as they render

1. **Attached** (E18): keyed on the row's own `ownership`, the same field the
   terminal branch reads. No fetch at all — asking the server for a pane we know
   is not there would turn a fact about the session into a failure message. The
   card shows the ask and one sentence saying we have no pane to answer on.
2. **Unparseable** (E16): the ask verbatim, the two universal options labelled
   and inert, and `DECISION_UNREADABLE` in words. It never invents the engine's
   list — which is the whole reason choice 2's scope stays reachable when the
   parser *can* read it.
3. **`trust_dialog`** (E17/C15): named by `pane_kind`, never by anything on the
   screen, and the card says in words that Enter there answers *"No, exit"*. The
   cursor is reported and not interpreted, on both sides of the wire.

And E20: a session whose bucket is not `needs_you` gets no card **and no pane
read** — the guard is the first thing `renderDecision` does, and the live test
asserts it as `scripted_runner.calls.count("pane") == 0` rather than as "nothing
is on screen", because a card built and then hidden would pass the second.

**The choices are inert in this build.** Nothing on any page posts to
`POST /api/sessions/{id}/permission`, so the card says so (`DECISION_INERT`)
rather than shipping three buttons that go nowhere — the same RD6 shape the
action list beside it already uses. Answering from the browser is not in T8.2's
Allowed Scope and is not smuggled in.

## Part 2 — the pane had no rule in `app.css` at all

Confirmed before touching anything: `grep -c '\.session-'` over `app.css`
returned **0**. Twenty-nine classes the pane wears — from the markup it ships as
and the nodes `session.js` builds — had no rule anywhere.

The live measurement at **390×844** found a real defect, not merely an unstyled
box:

| element | before | after |
|---|---|---|
| `body` | 844 tall, `scrollHeight` **1604** | 844 / 844 |
| `.main` | **1604** | 844 |
| `#flock-detail` | y=199, **h=1405** | y=199, h=645 (ends at 844) |
| `#session-view` | unbounded | h=589, `scrollHeight` 1349, scrolls |

The cause is one declaration: `.main` is a grid item of `.shell`, a grid item's
automatic minimum size is its **content**, and `.main` had `min-width: 0` for the
horizontal half of that rule and nothing for the vertical one. Every
`min-height: 0` and `overflow-y: auto` below it was therefore inert. This is the
same shape as the two defects the integration pass found one commit ago, and it
is **out of T8.2's stated Files** — recorded here as a scope increase rather than
slipped in, because the pane could not be styled without it.

`render_check.py` reported this page clean throughout: nothing overflowed
horizontally, nothing threw, and every `must_see` string was present. The only
check that sees it measures an element against the viewport.

## What this does NOT prove

- **That the parser survives an engine update.** It cannot: the choices are the
  engine's and move with its version. What is proved is that an unrecognised
  screen degrades.
- **Anything about a shape the corpus does not hold.** There is still no capture
  of a dialog with **more than three choices**, a **wrapped choice label**, a
  dialog **inside a subagent**, or the **`Tab to amend`** flow. The card renders
  whatever list it is handed and wraps with `overflow-wrap: anywhere`, but no
  test here has ever seen any of those four, and the two shapes that exist were
  both taken on `claude` 2.1.270 on one day.
- **That anybody can answer a dialog from Shepherd.** Nothing does. The card
  says so; T8.2 did not build it.
- **That the card is correct for a session whose bucket lags its pane.** It is
  keyed on `needs_you` per U11, so a session showing a dialog while the fold
  still calls it `running` gets no card. That is a deliberate reading of U11, not
  an oversight.
- **The scan cannot see a class chosen by anything but a literal or a simple
  ternary.** `test_the_stylesheet_owns_every_class_the_session_pane_wears` reads
  three literal forms plus `cond ? "a" : "b"`; a class built by concatenation
  would be invisible to it, and there is none in this file today.
