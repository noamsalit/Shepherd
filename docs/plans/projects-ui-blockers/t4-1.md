# T4.1 — the route table

Additions only. No logic was added to `routes.py`; the diff is four literal
blocks and one new module-level constant.

## The table

| method | template | tool |
|---|---|---|
| GET | `/api/projects/{project_id}` | `get_project` |
| GET | `/api/projects/{project_id}/repos` | `list_repos` |
| POST | `/api/projects` | `create_project` |
| POST | `/api/projects/{project_id}/rename` | `rename_project` |
| POST | `/api/projects/{project_id}/delete` | `delete_project` |
| POST | `/api/projects/{project_id}/repos/add` | `add_repo` |
| POST | `/api/projects/{project_id}/repos/remove` | `remove_repo` |

`BODY_ARGS`: `("name", "description")`, `("name",)`, `("on_running",)`,
`("root_path",)`, `("repo_id",)` — and **`project_id` in none of them**, in any
route, which is now asserted by name (see `t4-2.md`).

`GET /api/projects` is **unchanged** and still names `list_projects`;
`POST /api/projects` names `create_project`. One path, two methods, two tables —
which is why the tables are separate and neither has to encode a verb.

## `PROJECT_ID` in `routes.py`

New constant beside `SESSION_ID`, for the same reason that one exists: P13's
widened shadow test asserts on `routes.PROJECT_ID`, so the spelling the guard
checks and the spelling the table uses are one string.

## Two things this task had to absorb, neither of them in its Files list

1. **`tests/boundaries/consumer_manifest.json`.** `web/routes.py` is under Gate
   A's byte-freeze (D38). The digest in `files` was updated and **no
   `post_milestone` entry was added**, which is the plan's own rule for this
   case (T5.4: *"`app.css`, `app.js`, `index.html` are already in
   `regenerated_paths` and must NOT be added to `post_milestone` — that is the
   trap"*). `web/routes.py` is in `regenerated_paths` too, so its digest already
   differs from `baseline`, `moved_paths(baseline, files)` is unchanged, and the
   equality still holds. `baseline` was not touched; `rebase` was not touched.

   The first attempt *did* add a `post_milestone` entry and
   `test_a_rebase_declares_every_path_whose_digest_moved` refused it on the
   disjointness rule — the gate biting, on purpose, at the exact case its
   comment describes ("may never relaunder a path T24 already moved").

2. **Two fixtures that register tools.** `tests/web/conftest.py` and
   `tests/toolsurface/test_tools_m3.py::test_every_post_route_resolves_to_a
   _registered_tool` each register the sets the composition root registers, so
   that "every route names a registered tool" is not satisfied by a registry
   that is missing half the tree. Seven new routes meant both had to register
   `register_project_tools` as well. Both use `refuses_every_kill`: no web test
   drives a project delete against a running session, and a fixture that
   answered "killed" for a session it never touched would let a delete take a
   live session's rows.

## What T4.1 does **not** prove

- **That any page calls these routes.** The table is a value; Phase 9 is where a
  person drives it.
- **That the JSON body shapes match what the page will send.** Only that the
  fields the table forwards are properties of the tool's schema — which is
  `test_routes_m3.py`'s gate, and it checks `BODY_ARGS` only.
- **Anything about `GET`/`POST` on `/api/projects` colliding.** The two tables
  are consulted by two functions; no test here drives a `GET` against
  `resolve_post` or the reverse.
