**Checkpoint type: `decision`.** A new numbered spec row. §0 forbids taking one
quietly, so it is written in the same task that performs the relocation, with
its date and its reasoning, exactly as T5.1 wrote D66.

* §3 gains **D67**, after D66.
* §3's headline count moves `66 → 67` and `D1–D66 → D1–D67` (F15). T5.1 left it

## What relocated, and what that cost

`session.js`'s contracts are unchanged and every one of its slot ids is
unchanged — `session-view`, `session-title`, `session-chip`, `session-state`,
`session-why`, `session-actions`, `session-rename`, `session-local-only`,
`session-banner`, `session-terminal`, `session-input-note`. All 16 node ids in
`test_session_page.py` and all 10 in `test_session_wiring.py` still collect.

**`terminal.js` and `sse.js` are byte-unchanged.**
`git diff --stat src/shepherd/web/static/terminal.js src/shepherd/web/static/sse.js`
prints nothing. So A11 does not fire: the `post_milestone` count stays at
**six**, and the plan is not wrong by one.

What moved *in* is the stopped-row logic that lived in `fleet.js`. U7 fixes the
card at four items, so D21's `next_actions[]` has nowhere on the card to be, and
§12 already placed the list in the Session view header. Every rule the list
carried moved with it rather than being quietly dropped — RD6's
labelled-and-inert kinds with the milestone named, N10's `[why?]` disclosure and
its "the model lane is not built" wording, §14's `nothing to do`, G-M2-7's
targetless `external`. A relocation that loses the rules is a deletion with a
better name.

One refactor came out of it: `notYetReason(kind)` answers the string or `null`,
so `disabled` is written once on one inert path with two reasons. Writing it in
each branch is the same render performed twice, and
`test_render_session_performs_every_assignment_the_spec_requires` refuses a
duplicated render — a second copy is where the two eventually stop agreeing.
`REQUIRED_ASSIGNMENTS` gained the five new lines and lost three, each with the
requirement it discharges.

## The one retirement

`tests/web/test_fleet_page.py::test_stopped_row_renders_why_and_first_action`,
with the plan's decision string —
`"§12 (the Session view header already carries the list) with §3 D67"` — and a
reason well over 80 characters. Its successor,
`test_the_session_pane_renders_why_and_every_action`, is **strictly stronger**:
the collapsed row rendered `actions[0]` because it had space for one, and the
pane renders every action with its ordinal and its source. What retires is the
truncation, not the rule.

`test_fleet_page.py` keeps its filename and its other sixteen ids as body
rewrites. Renaming them with the file would have retired seventeen frozen ids to
say nothing new.

## The mutation that mattered

**M8 survived.** `actions.slice(0, 1).forEach(...)` kept the ordinal, the source
and the class, so every assertion in both the successor and its `test_fleet_page`
counterpart stayed green while the pane rendered exactly the one action the
retired test settled for. The word "every" in the successor's own name was not
being checked. Both tests now name the truncating shapes — `.slice(`,
`actions[0]`, `.at(0)`, `actions.shift(` — and assert `actions.forEach(`.
Re-planted as M8b/M8c: both red.

## What this does not prove

Not a pixel. Every rendering claim in `test_flock_page.py`,
`test_fleet_page.py`, `test_palette.py` and `test_session_page.py` is a scan of
the bytes the server serves — there is no browser and no JS runtime on this host
(D51, K8). `render_check.py` drives a real Chromium over
`tests/web/fixtures/shell_harness.html`, which proves the **stylesheet's** class
contract and document overflow at two widths; it does not execute `flock.js` or
`session.js`, because the harness deliberately loads no module. Phase 10's live
check against the served page, and the human look there, are what close this.

It also does not prove the pane *renders* in the shipped shell, because the
shipped shell does not carry its slots yet. See the shell contract in T6's
report.
