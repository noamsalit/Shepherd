## T0-1-1 · `importorskip` on pytest 9.1 catches **`ModuleNotFoundError`**, not `ImportError`

- **Symptom:** the exit criterion *"the suite collects and passes with playwright uninstalled"*
  was proved by hiding the package behind a `sys.meta_path` finder that raised `ImportError`.
  Collection **errored** anyway, with the traceback landing on line 32 —
  `pytest.importorskip("playwright")` itself.
- **What was tried:** read `_pytest.outcomes.importorskip`. Since **pytest 9.1** the default
  `exc_type` is `ModuleNotFoundError`; a bare `ImportError` propagates. The blocker was changed
  to raise `ModuleNotFoundError`, which is also what a genuinely absent package raises, so the
  simulation got *more* faithful rather than looser.
- **What it blocks:** nothing. It would have blocked anyone re-running this proof.
- **Owner:** T0.1.

Installed pytest here is **9.1.1**. The consequence beyond this task: any `importorskip` guard
in this tree only fires for a module that is genuinely missing. A module that exists and raises
`ImportError` from its own body — a broken install, a missing shared library — is **not**
skipped, it errors. That is the right behaviour and it is worth knowing before someone reads a
skip as "the dependency is optional".

## T0-1-2 · a by-path module cannot define a `dataclass` unless it is in `sys.modules`

- **Symptom:** adding `@dataclass(frozen=True) class Args` to `tools/render_check.py` broke
  collection with `AttributeError: 'NoneType' object has no attribute '__dict__'` from
  `dataclasses._is_type`.
- **What was tried:** `dataclasses` resolves a field's annotations through
  `sys.modules[cls.__module__]`. A module built by `importlib.util.module_from_spec` and
  executed without being registered is not there, so the lookup returns `None`. The loader in
  `tests/tools/test_render_check_args.py` now registers the module **before** `exec_module`,
  which is the documented recipe.
- **What it blocks:** nothing now. Every later task that loads a `tools/` module by path
  (T10.1 is the next) inherits the fixed loader pattern.
- **Owner:** T0.1.

## T0-1-3 · the six `must_see` strings are a **contract on Phases 5–9**, decided here

- **Symptom:** `PAGES` must carry a `must_see` string *"present on the served page, not merely
  on the prototype"*, but the served pages do not exist yet — Phase 5 builds the roots and
  6–9 the bodies. The plan and `docs/design/ui-decisions.md` specify no page text, and Queues
  and Kanban are explicitly **placeholders with no content this milestone**.
- **What was tried:** the prototype's strings (`"which sessions are stuck"`, `"payments-api"`)
  were rejected: the first is prototype copy nobody has committed to, and the second is
  *seeded data*, which would make the checker fail on an empty install. The rule chosen is
  uniform and is the weakest thing all six pages can honour, including the two placeholders:

  | page | `must_see` |
  |---|---|
  | `shepherd` | `Shepherd` |
  | `flock` | `Flock` |
  | `queues` | `Queues` |
  | `projects` | `Projects` |
  | `kanban` | `Kanban` |
  | `settings` | `Settings` |

  **Each page root renders its own name as visible text inside `#page-<name>`.** Not in the
  nav — the checker reads `#page-<target>.inner_text()`, so a heading in the side pane does
  not satisfy it.
- **What it blocks:** **T5.3** (the six page roots), and T6.1 / T7.x / T9.x for their bodies.
  A phase that wants a stronger string should *strengthen* the table in `PAGES` as it builds
  the page — that is the table's whole purpose, and changing it is cheaper than a page that
  cannot show its own name.
- **Owner:** T0.1, handing to T5.3.

## T0-1-4 · `tests/daemons/test_sessiond_socket.py` failed once in a full-suite run, then did not

- **Symptom:** the first whole-suite run after this task's tests landed reported
  `FAILED tests/daemons/test_sessiond_socket.py::test_restart_after_clean_shutdown_binds_without_eaddrinuse`.
- **What was tried:** re-run in isolation — 8 passed, exit 0. Re-run of the **whole suite** —
  exit 0. A third whole-suite run with playwright hidden (so this task's four browser tests
  skip) — exit 0. The test's waits are `await_true` deadlines around a unix socket under
  `tmp_path`; this task's new tests launch chromium four times in the same run, and the most
  likely explanation is deadline pressure from that load, not the socket. **This is a
  hypothesis, not a measurement** — the failure's own message was not captured before the
  re-run, which is the mistake to avoid next time: capture the failure text before you re-run.
- **What it blocks:** nothing, and it must not be "fixed" from here — it is outside T0.1's
  Allowed Scope and outside `src/`, which Phase 0 does not touch at all.
- **Owner:** unowned. If T10.2's whole-tree gate sees it again, it gets an id there.

## What this task actually proved

- The checker **reaches a served page**: `--url http://127.0.0.1:8765/good.html` → `0 failures`,
  exit 0, twelve screenshots (six pages × two viewports).
- The checker **fails on a page it should fail on**: the same page with `#page-settings`'
  text replaced → `FAIL [phone] settings is missing 'Settings'`,
  `FAIL [desktop] settings is missing 'Settings'`, exit 1. A checker nobody has seen fail is
  not a checker.
- It **still runs against a file**: `--file …/good.html` → exit 0, screenshots beside the file.

## What it does **not** prove

That any page of the product is correct. Nothing in `src/` was read, run or touched. The
fixture the checker was driven against was written by the test to satisfy it, which proves the
*tool*, and nothing about the shell Phase 5 will build.
