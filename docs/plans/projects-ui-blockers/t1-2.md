# T1.2 — models and rows

## T1.2 · `OnRunning.KILL = "kill"` is refused by the tmux blast-radius gate · isolated to that one literal, three options named, none taken · **blocks T1.2's exit, T1.4, and therefore Phase 1's green boundary** · owner: **router / owner decision needed**

**Symptom.** With `OnRunning` added exactly as the plan's Produces specifies
(`REFUSE`/`KILL`/`ORPHAN`, values `"refuse"`/`"kill"`/`"orphan"`), T1.2's
Required Check `pytest tests/boundaries -q` fails three rules:

```
FAILED tests/boundaries/test_tmux_blast_radius.py::test_kill_server_is_never_a_command_word_in_src
FAILED tests/boundaries/test_tmux_blast_radius.py::test_the_teardown_verb_is_spelled_in_exactly_one_module_in_src
FAILED tests/boundaries/test_tmux_blast_radius.py::test_a_server_wide_teardown_is_bounded_to_a_throwaway_socket
E  '/root/Shepherd/src/shepherd/store/models.py:69: a server-wide teardown has no
   place in src/, and tmux resolves a command-name prefix to one'
```

**Why.** `shepherd.runner.tmux_cmd.is_server_teardown("kill")` returns `True` —
`kill` is a prefix of `kill-server`, and the predicate refuses *ambiguous*
prefixes too, on purpose (it is also a prefix of `kill-session`). The gate's
`src/` branch — `kill_server_violations`, `tests/boundaries/test_tmux_blast_radius.py:359-385`
— scans **every non-docstring string constant in every position** in `src/`,
because `teardown_mentions`'s docstring records the measurement it was widened
on:

> *"Measured over `src/` before this widened: **one** hit, the guard's own
> canonical constant, and nothing else — so the wider scan costs no false
> positive here."*

**That measurement is exactly what migration 004's delete semantics falsify.**
`"kill"` in `models.py` is in no command-name position and reaches no tmux; it
is the second of three `on_running` choices. It is the gate's first false
positive, and the gate's own justification for its scan width is the claim that
it has none.

**What was tried.** The cause was isolated to the single literal with a
controlled substitution, run and reverted inside the same command:

| `OnRunning.KILL` value | `pytest tests/boundaries -q` |
|---|---|
| `"kill"` (the plan's value) | **3 failed**, 102 passed |
| `"terminate"` (probe only, reverted) | **105 passed**, exit 0 |

Nothing else in T1.2 is implicated: `mypy --strict src/shepherd/store` is clean
either way, and the other four T1.2 tests
(`test_the_reserved_project_id_has_one_definition_site`,
`test_a_delete_outcome_carries_every_field_the_refusal_needs`,
`test_a_workspace_carries_a_description_and_no_root_path`,
`test_a_repo_no_longer_carries_the_project_it_belongs_to`) pass. The tree is
left carrying `"kill"` — the plan's value — so the finding is visible rather
than papered over.

**The three options, none taken, because this is a decision and not a repair.**

1. **Change the literal** (e.g. `KILL = "terminate"`). Green immediately, no
   gate touched. Cost: it reverses the Behavior Contract's
   `on_running ∈ {"refuse", "kill", "orphan"}`, which is also written into the
   `input_schema` `enum` (D-blast classes), the route table's `BODY_ARGS`, and
   the Projects page's three-choice dialog. **Cheapest now and dearer every
   phase** — no consumer exists yet, since Phases 3–9 are unbuilt.
2. **Exempt `models.py` from the gate.** Cost: the gate identifies its one
   permitted module *by property* (`guard_module()` finds the sole definer of
   `check_tmux_argv`) precisely so it cannot be switched off by moving a file —
   `"a rule that can be switched off with git mv is not a rule, and this package
   has shipped two of those"`. A path exemption reintroduces what that
   sentence was written against.
3. **Narrow the gate to command-name positions.** Defensible on the merits —
   the property is about a word tmux *reads as a command name* — but it is a
   change to the guard that a reboot incident paid for, it needs its own
   negative control (MUT-G4's `self._checked("kill-serv")` is the case the wide
   scan exists to catch, and it is a call **argument**, not a command-name
   position), and it is in no Phase 1 task's Files.

**I did not choose.** The plan pre-decides neither, all three are outside
T1.2's Allowed Scope (`models.py`, `rows.py`), and option 2 and option 3 both
edit a safety boundary. Per the dispatch: *"If a required check fails and you
cannot fix it inside your Allowed Scope, stop and say so rather than widening
scope to make it pass."*

**What it blocks.** T1.2's exit ("the 105 boundary rules green"); T1.4, which
consumes `OnRunning`; T1.8, whose Required Checks include
`pytest tests/boundaries -q`; and therefore Phase 1's green boundary at T1.10.
