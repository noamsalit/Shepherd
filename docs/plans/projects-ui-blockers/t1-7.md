# T1.7 — `bind_cwd_to_repo` binds to Unassigned

## T1.7 · the four-branch table landed as written, and F10's hazard was live · owner: builder (Phase 1)

Three of the four branches previously called
`upsert_workspace(basename(cwd), cwd)`; they now return
`UNASSIGNED_PROJECT_ID` and create nothing. The new-repo branch calls
**`store.upsert_repo`** — the unattached verb — and not `add_repo`. The
distinction is the whole of F10 and it is now a property of the two verbs'
signatures rather than of a reviewer's attention: `upsert_repo` has no
`workspace_id` parameter to pass.

`_workspace_name` was deleted. The one place a basename is still needed (the
repo's *name*) spells `Path(root).name or "local"` inline, so a reader does not
meet a helper whose name says *workspace* on a line that means *repo*.

## T1.7 · the steady-state branch is the only place D60 is decided

`_resolve_project(store, repo_id)` is three lines and one sentence:
`projects[0] if len(projects) == 1 else UNASSIGNED_PROJECT_ID`. Exactly one
project is the only unambiguous answer; two is D60 (a discovered session cannot
be asked which it meant) and none is D59. Both land on the reserved project,
where a person can move them, rather than on a guess a person would have to
notice in order to correct.

**The negative control is inside E4.** `test_a_repo_in_two_projects_binds_a
_discovered_session_to_unassigned` first asserts, through
`test_the_new_session_lands_in_that_project`, that **one** project resolves to
itself. Without that half, a `_resolve_project` that always returned the
reserved id would pass the ambiguity test and the branch would be certified by a
control that exercises one side of two — which is the lesson Phase 0 paid for.

## T1.7 · P4's matrix, and what "never raises" now costs

`test_bind_cwd_to_repo_never_raises_over_the_cwd_matrix` runs nine cwd shapes —
repo, subdir, worktree, bare, missing, trailing slash, empty string, `/`, a path
with a space — and asserts a non-empty `workspace_id` on every one.
`RepoBinding.workspace_id` is still non-optional and the *"never raises"*
docstring is unchanged and true. The verb is now **cheaper** to keep true than
before: three of its four branches no longer write at all.

## What T1.7 does **not** prove

- The hook lane's other three call sites (`hook_lane.py:165,179,203`) under
  load. Only that each gets a `RepoBinding` with a non-null `workspace_id`.
- That a session bound to `unassigned` is *findable* by a person. The Projects
  page is Phase 9; today the evidence is a row on Flock under `Unassigned`.
- That `projects_for_repo`'s ordering matters. It is `ORDER BY workspace_id`
  for stability; `_resolve_project` only ever reads `len()` and `[0]` of a
  one-element list.
