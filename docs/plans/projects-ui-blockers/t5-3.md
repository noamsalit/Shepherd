## Three decisions a reader should not have to reconstruct

**The topbar heading is `id="topbar-title"`, not the prototype's
`id="page-title"`.** `render_check.PAGE_ROOT_SELECTOR` is `[id^="page-"]`, so
porting the prototype's id verbatim makes a permanently-visible heading count
as a seventh page root. Every exclusivity assertion then fails at Phase 10 with
a message about routing that has nothing to do with routing. The shipped page's
own gate catches it here instead: mutation C below.

**The root that ships visible is `#page-flock`, not `#page-shepherd`.** The
prototype ships Shepherd. The frozen assertion
`test_the_chat_view_ships_hidden_and_the_fleet_ships_visible` exists because a
page whose module graph failed to load should show the M1 surface that needs no
orchestrator, not an empty conversation frame claiming a master that never
answered. `app.js` navigates to Shepherd on the first paint (§12 page 1 is the
default landing), so the static attribute is the honest **degrade** and not the
intended arrival. Both properties hold at once.

**`app.js` binds each nav entry by id rather than by delegating on
`data-page`.** The cost is stated rather than hidden: the six page names are
spelled in `app.js` as well as in `index.html`. The benefit is that a
disagreement is loud — `getElementById` returns `null` and the page throws on
load, which `render_check.py` reports as a page error — where delegation binds
nothing, silently. `data-page` remains the attribute the live checker drives,
and `test_shell.py` asserts the markup carries it for all six, so neither
spelling can drift alone. It is also what keeps
`test_every_id_in_the_chat_view_is_wired_by_the_script`'s rule true of the
six-entry nav: the bootstrap that owns routing wires `#nav-chat` and
`#nav-fleet` **by name**, and that assertion is satisfied by the code rather
than by a comment (`code_only()` strips comments before it looks).

## What this does NOT prove

- **No page has content.** The Flock root wraps the *old* fleet markup, and
  `app.css` no longer carries a single rule for `.fleet-view`, `.masthead`,
  `.chat-view`, `.empty-state` or `.session-view` — T5.2 replaced the whole
  stylesheet. Those pages are visually unstyled until Phases 6, 7 and 9. This
  task proves the shell, the reset, the routing and the paperwork.
- **The shipped page has not been rendered in a browser.** `render_check.py`
  ran against T5.2's harness, not against `index.html`: the shipped page is an
  ES-module document that a `file://` load cannot resolve, and driving it over a
  real origin needs a live `controld` with real API answers — which is
  `tests/web/test_render_live.py`, **T10.1's task**, and building it here would
  be reaching into a later phase. What is proved statically is that the markup
  satisfies every contract the live checker drives, read out of that checker's
  own constants.
- **A JS-built card is not covered.** `test_every_card_in_the_shipped_markup_declares_its_bucket`
  scans static markup. `flock.js` builds its cards in script, and holding the
  bucket-class rule on the *built* card is T6.1's, at the seam that can see one.
- **Nothing about a pixel.** Contrast, wash and overflow are `app.css`'s and
  were proved by T5.2; the human look is Phase 10's checkpoint.
