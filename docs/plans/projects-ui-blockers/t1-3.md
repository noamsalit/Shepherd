# T1.3 — reads

## T1.3 · the read verbs are tested at the **connection** seam, not through `Store` · no blocker · owner: builder (Phase 1)

`reads.py` presents a `sqlite3.Connection` interface (ADR-7), so the seven new
tests take one directly rather than going through `Store`. Two consequences
worth recording:

* rows are planted with **literal SQL**, not with `writes.py`. A fixture built
  by the write verbs would recompute the expected answer the way the read verb
  does, and the test could then never disagree with the code.
* the tests could be written and shown red **before** `Store` learned the verbs
  (T1.6), which is what kept T1.3's RED honest inside a phase whose ordering is
  otherwise circular (see t1-5.md).

## T1.3 · `repo_counts`'s "one statement" is asserted through a tracing connection

`test_repo_counts_answers_every_project_in_one_statement` installs
`connection.set_trace_callback` and asserts `len(statements) == 1`. No
assertion on the *result* can tell one `GROUP BY` from an N+1 loop — both
return the same mapping — so the claim in M4 is only a claim until the
statements are counted. The same shape is used one layer up in T1.10
(`test_the_project_list_issues_a_bounded_number_of_statements`), where the
control is the measurement at **two fixture sizes**: one project and eight cost
the same statements.

## T1.3 · `project_last_activity` omits a project with no session, rather than mapping it to `None`

The return type is `dict[str, str]`, so absence is the only spelling of "never".
A `None` value would be a second spelling of the same fact and the projection
would have to handle both. `test_project_last_activity_is_derived_from_sessions`
asserts the absence directly (`w-quiet` is not a key).

## T1.3 · `running_sessions_for` is `ended_at IS NULL`, not `state = 'running'`

A session in `starting` or `needs_you` is just as alive, and `state` is a fold's
opinion while `ended_at` is a fact. The negative control in
`test_running_sessions_for_returns_only_the_unfinished_ones` is `s-done`: a
verb that forgot the clause would name it as a reason to refuse a delete that
should have gone through.

## What T1.3 does **not** prove

- That `list_workspaces` is safe to index. It is not, and E22 pins that: the
  verb is unchanged and `[0]` is the seeded `"Unassigned"`. The repair is at
  the call sites (T1.5).
- That any of these verbs is reachable from `Store`. That is T1.6, and until it
  landed these seven had zero callers.
- Anything about `fleet()`. Its INNER JOIN and its ordering are untouched, and
  the P2 invariant that depends on it is proved in T1.4, not here.
