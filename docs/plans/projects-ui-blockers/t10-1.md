## The blind spot, and what closed it — with the part that did not

The pass found a defect `render_check` **could not see**: `.herd` declared two
grid rows while carrying three items, so the three panes were crushed to a
strip at the bottom — and the checker reported *12 pages · 0 failures*.
Reverting it turned nothing red but the byte-freeze digest.

**The task named a root-level viewport check as the fix. Measured against the
real page, that premise is false, and the numbers are why.** With the two-row
`.herd` injected into the shipped page over a real `controld`:

| | root top → bottom | viewport | `scrollHeight - clientHeight` |
| --- | --- | --- | --- |
| healthy, desktop | 56 → 900 | 900 | 0 |
| **M5 (`.herd` 2 rows), desktop** | **56 → 900** | 900 | **0** |
| healthy, phone | 56 → 844 | 844 | 0 |
| **M5, phone** | **56 → 844** | 844 | **0** |

`#page-flock`'s own rectangle is **byte-identical** in both states. What moved
is one level down: `.herd-col` went from `top=130 h=770` to `top=801 h=99`.
Nor does the grid's shape give it away — Chromium's computed
`grid-template-rows` reports the **implicit** track too, so both states read as
three rows (`42 32 770` healthy, `42 703 99` broken). **No per-root rectangle
can distinguish those**, and there is no generic property of a page root that
does.

So M5 is *not* closed by this tool, and this ledger says so rather than
implying otherwise. It is closed by
`tests/web/test_shell_live.py::test_each_page_root_fills_the_column_it_is_given`
(committed at `cf08139`), which measures the panes' own boxes — **cited, not
re-proved here**: re-planting M5 against that test means writing to `app.css`,
which carries another agent's uncommitted work in this checkout, and
`git checkout -- <path>` on a dirty tree goes to HEAD. The integration ledger
records it as rows M5b and M7, both red. Spelling the panes' selectors a second
time inside `render_check.py` would be the rule-written-twice drift this repo
has been bitten by three times.

**What the new check does close** is the *other* defect of the same family, and
the tool was equally blind to it. `.main > .detail` carries `flex: 1`; defect #3
was the Shepherd page losing it and becoming a content-height box at the top of
an empty column with its composer unpinned. That one **is** a root-level fact:

| | root bottom / viewport |
| --- | --- |
| healthy, all twelve readings | **1.00** |
| M7 (`.detail` loses `flex: 1`), phone | 0.26 |
| M7, desktop | 0.25 |

Twelve healthy readings land exactly on the fold. `FILL_FLOOR = 0.75` sits
between 1.00 and 0.25 with room on both sides, because this is a check for
*collapsed*, not a pixel comparison.

### The rule is opt-in, and that is a finding, not a convenience

Made unconditional, the fill rule turned **four of the tool's own fixtures
red** (`tests/tools/test_render_check_args.py`) — pages whose roots are
content-height `<section>`s, which are perfectly good pages. "Every page root
fills the column it is given" is a claim about *this shell's* layout contract,
not a property of web pages, so it is `--must-fill` / `must_fill=True`,
alongside the `--fail-on-empty` precedent. Containment and non-zero height stay
unconditional: those **are** universal.

## Three mechanics inherited, and a fourth found here

1. **`SocketPathTooLong`.** The abstract-socket budget is 107 bytes. Only
   `XDG_RUNTIME_DIR`/`TMPDIR` go to a short `/tmp/shp-*`; data, config, state,
   cache and `HOME` stay in `tmp_path`, and the escape assertion is kept in
   full — it just has two allowed roots now instead of one.
2. **`pytest.importorskip("playwright")` is the module's first executable
   statement.** `playwright` is undeclared, and `-m 'not live'` deselects
   *after* collection has already imported the file.
3. **`tools/` is importable from nowhere** (`pythonpath = ["src"]`). Loaded by
   path, registered in `sys.modules` **before** `exec_module` or it cannot
   define a dataclass, and unregistered again if `exec_module` raises.
4. **New: `PLAYWRIGHT_BROWSERS_PATH` must be pinned *before* the XDG
   redirect.** Playwright resolves chromium under
   `$XDG_CACHE_HOME/ms-playwright`, so the redirect that keeps `controld` out of
   the developer's home also hides the browser from the check about to run it.
   The failure reads `Executable doesn't exist at …/ms-playwright/…` — an
   environment fact wearing a code defect's clothes. Cost: one confusing run.

## What the live check still does not prove

It is the last gate before a person looks, so the edges are worth stating
exactly.

* **Not correctness of any layout.** The assertions are: no console error, the
  page's own name inside its own root, exactly one root visible, ≤1px of
  horizontal overflow, and the root on-screen and filling its column. A page
  can satisfy all five and be ugly, mislabelled, or wrong. That is what the
  twelve screenshots are for, and why this task's checkpoint is a human one.
* **Not anything inside a page root** — measured above, and M5 is the worked
  example of what that costs.
* **Not a phone's real browser, not a tunnel, not a slow network.** Six pages ×
  two viewports in headless chromium on this host.
* **Not the terminal.** No owned session's WebSocket is driven.
* **Not the Shepherd conversation against a real master.**
* **Not much data.** One project and one session are seeded, so nothing scrolls
  and no list is long. A defect that only appears at fifty sessions is invisible
  here.
