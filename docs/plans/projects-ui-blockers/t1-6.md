# T1.6 — `Store` delegation

## T1.6 · the two properties are made **total over a named set**, not over a remembered list · owner: builder (Phase 1)

`PROJECT_WRITES` and `PROJECT_READS` are module constants, and
`test_every_project_verb_is_refused_once_the_store_is_closed` asserts
`len(refused) == len(PROJECT_WRITES) + len(PROJECT_READS) + 1` before running
the loop. Without that line, a verb dropped from the `refused` list passes
silently — which is the failure mode the file's own docstring describes for the
M3 verbs that were tested everywhere except on `Store`.

`test_every_project_write_crosses_the_one_writer_thread` asserts on
`writer_thread_idents()` rather than on return values, because a verb wired to
`self._read()` answers **correctly** on a read-write database and quietly hands
D37 a second writer.

## T1.6 · `Store.upsert_repo` lost its `workspace_id` and kept its name (F10)

It is the verb that writes an **unattached** repo row — what discovery needs.
`add_repo` is the one that also registers it to a project. Keeping one name for
both would have made F10's hazard a one-word edit away: attaching every
discovered repo to `unassigned` widens `_registered_roots("unassigned")` to
every repo the machine has ever seen.

## What T1.6 does **not** prove

- That the delegation is *thin*. `test_the_m1_and_m2_write_implementations_live
  _in_store_writes` asserts `db.py` spells no SQL, which is the closest
  available proxy, and it is not the same claim.
- That any of the eleven verbs is called by anything above `store/`. Five of
  them still have no caller at the end of Phase 1.
