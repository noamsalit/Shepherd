## The two `innerHTML` assignments this task owned

The prototype's `renderLegend()` (line 2520) and `BACK_BUTTON(level)` (2858)
both concatenated SVG into a sink. §13 permits a sink only when its right-hand
side is a single quoted literal with no concatenation, and neither was one. Both
are `document.createElementNS` here. **`createElementNS`, not `createElement`:**
an `<svg>` built in the HTML namespace renders as nothing at all, so the
namespace is what the test asserts rather than the element name.

**Which branch of two this certifies.** The other four of the prototype's eight
sinks — `bylineMark()` (2688) and `renderDetail()`'s three (2796, 2814, 2837) —
are **not ported**, because their inputs are the prototype's mock `TRANSCRIPT`,
`PROMPT` and `WHY` tables and no endpoint in this build serves a session
transcript. `renderDetail`'s real counterpart is `renderSession`, which renders
the terminal instead. So the no-sink evidence covers the two sinks that exist in
shipped code; it does not cover four that were never written. Said here rather
than counted as six.

## The red is now a named debt, not an unexplained failure

The three tests above are **green**. What replaced them is
`PENDING_SHELL_WIRING` in `tests/web/test_session_wiring.py`: one entry, the one
line that pays it, and `test_the_pending_shell_wiring_is_exactly_what_is_owed`
pinning the contents as a whole set. **The integration pass empties the dict and
deletes that test.**

It is deliberately **not** `UNREACHABLE_BY_DESIGN`. That constant means *not
meant to be reachable*; folding a not-yet-wired module into it asserts the
opposite of what is true and makes the page permanently dead by definition.
`shipped - reached` is unchanged and excuses nothing new — widening it would
have been the laundering.

**The debt turned out to be an import line, not a module.** `flock.js` *is*
reached: `session.js` imports `element` and `showLevel` from it and `session.js`
is on the graph. So the reachability walk is satisfied and the page still never
draws, because the bootstrap calls a `render` it imported from a module that no
longer ships. **Loaded is not driven**, and a walk structurally cannot see the
difference, so that half is asserted on `app.js` itself.

`STALE_SPECIFIERS` lets the walk skip **only** the one declared dead edge. M17
plants an undeclared missing module and the walk still bites.

## Two findings in the stylesheet, reported rather than fixed

`app.css` is T5.2's file and is not this task's to edit.

1. **`.legend-note { display: none }` below 900px** (`app.css:1587`). The
   stop-summary strip carries `.legend-note`, so `#unknown-rate`,
   `#low-confidence` and `#unclassified` are hidden on a phone. Principle 5 says
   the unknown rate is counted and **displayed**, never hidden, and B3 kept the
   strip for exactly that reason. The Flock page is also the root that ships
   visible, so this is the surface a no-JS load shows.
2. **`.col-head` is `text-transform: uppercase`, and Playwright's
   `inner_text()` returns text-*transformed* text** — so the projects pane's
   head renders `FLOCK` and cannot satisfy `render_check`'s literal `Flock`. The
   general rule, which cost more than one phase: use `text_content()` when you
   mean the string in the markup and `inner_text()` when you mean the string on
   screen; `render_check` means the second, which is right, and the consequence
   is that any page whose only self-naming sits under a transform fails a
   *content* check for a *CSS* reason. Before
   T6.1 the only source of that literal inside `#page-flock` was a card title in
   the *projects* column of the harness; moving the cards to the sessions column
   — where they belong — made the check fail at phone width and pass at desktop,
   which is the shape of a check that was passing for the wrong reason.
   `#flock-heading` now supplies it from inside `.legend`, the one strip visible
   at every level of U9's drill-down. It carries **no class**, deliberately:
   inventing a rule name `app.css` does not define would be a contract nobody
   agreed to. **The shipped shell does not need it** — `index.html`'s Flock
   masthead already carries `<h1>Flock</h1>`, untransformed — so `#flock-heading`
   is a harness-only slot and is *not* in the contract this task asks for.


## Two things asked for that this page does not have

**A privacy property proved in pixels.** There is no redaction rule on the Flock
page to prove. Everything it renders — a title, the ask verbatim, a classifier's
`why`, a relative time, three counts — is the operator's own work shown back to
them, and §13's rule here is about *injection*, not about what a person may
read. The nearest thing to a privacy property in this area is D25/K14 — the page
opens no log and no transcript — and it is asserted as an absence over the
shipped bytes (`test_expansion_reads_no_log_and_no_transcript`), which is the
right shape for "never fetches" and the wrong shape for "never displays".
Recorded as *not applicable with a reason*, rather than left unmentioned.

**A `page-` id minted by this page.** None. `flock.js` reads `#page-flock` and
writes no id at all; `session.js` writes none either. Pinned by
`test_the_page_never_mints_a_seventh_page_root` and mutation-proved (M3), since
the prototype's `id="page-title"` is one copy-paste away and
`PAGE_ROOT_SELECTOR` is `[id^="page-"]`.
