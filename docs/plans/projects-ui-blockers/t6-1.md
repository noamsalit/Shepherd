## The two `innerHTML` assignments this task owned

The prototype's `renderLegend()` (line 2520) and `BACK_BUTTON(level)` (2858)
both concatenated SVG into a sink. §13 permits a sink only when its right-hand
side is a single quoted literal with no concatenation, and neither was one. Both
are `document.createElementNS` here. **`createElementNS`, not `createElement`:**
an `<svg>` built in the HTML namespace renders as nothing at all, so the
namespace is what the test asserts rather than the element name.

**Which branch of two this certifies.** The other four of the prototype's eight
sinks — `bylineMark()` (2688) and `renderDetail()`'s three (2796, 2814, 2837) —
are **not ported**, because their inputs are the prototype's mock `TRANSCRIPT`,
`PROMPT` and `WHY` tables and no endpoint in this build serves a session
transcript. `renderDetail`'s real counterpart is `renderSession`, which renders
the terminal instead. So the no-sink evidence covers the two sinks that exist in
shipped code; it does not cover four that were never written. Said here rather
than counted as six.

## The bug the payload half caught that a scan could not

`fleet_tree`'s workspace entries carry **`project_id`** (D22: a project *is* a
workspace and the consumer-facing key is `project_id`) while the session rows
inside them carry `workspace_id`. The first draft of `projectButton` read the
row's spelling off the workspace, which renders a list of `undefined` projects
that select nothing. Caught by
`test_the_flock_page_reads_the_keys_the_tree_emits`, which asserts the key set
over HTTP and then asserts the page reads it. A source scan can never see this.

## Two findings in the stylesheet, reported rather than fixed

`app.css` is T5.2's file and is not this task's to edit.

1. **`.legend-note { display: none }` below 900px** (`app.css:1587`). The
   stop-summary strip carries `.legend-note`, so `#unknown-rate`,
   `#low-confidence` and `#unclassified` are hidden on a phone. Principle 5 says
   the unknown rate is counted and **displayed**, never hidden, and B3 kept the
   strip for exactly that reason. The Flock page is also the root that ships
   visible, so this is the surface a no-JS load shows.
2. **`.col-head` is `text-transform: uppercase`**, so the projects pane's head
   renders `FLOCK` and cannot satisfy `render_check`'s literal `Flock`. Before
   T6.1 the only source of that literal inside `#page-flock` was a card title in
   the *projects* column of the harness; moving the cards to the sessions column
   — where they belong — made the check fail at phone width and pass at desktop,
   which is the shape of a check that was passing for the wrong reason.
   `#flock-heading` now supplies it from inside `.legend`, the one strip visible
   at every level of U9's drill-down. It carries **no class**, deliberately:
   inventing a rule name `app.css` does not define would be a contract nobody
   agreed to.
