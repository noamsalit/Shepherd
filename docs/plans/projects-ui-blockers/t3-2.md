# T3.2 — compose wiring

## T3.2 · the composed test went in `test_compose_m4.py`, not `test_composition_root.py` · owner: builder (Phase 3)

**Symptom.** The plan's Files for T3.2 name
`tests/boundaries/test_composition_root.py`, and its exit criterion is *"a
composed process answers all seven"*. That module composes nothing: it is 114
lines of AST and line-count rules over `src/` — `test_nothing_imports_daemons`
and `test_no_source_file_exceeds_600_lines`. It has no store, no host, no
`SocketPlan`, and nothing in `tests/boundaries` builds one.

**What was tried.** The assertion was written where the seam already exists.
`tests/toolsurface/test_compose_m4.py` has a `World` fixture that calls the
shipped `compose.compose_tool_surface` with a `ScriptedHost` under `tmp_path`,
and `test_the_master_tools_are_registered_by_the_composition` is the exact shape
this task needs. `test_the_project_tools_are_registered_by_the_composition` was
written beside it, using the same enumerate-then-compose pattern so no list in
that file has to be maintained. **The seam is the plan's** — *"integration:
`invoke()` through the registry with a composed chokepoint"* — and
`tests/toolsurface` is inside T3.2's own Required Checks, so the check that
proves the criterion is run by the command the plan names. Only the file
differs.

**What it blocks.** Nothing. Recorded because a plan's Files list is a contract
and this entry is the deviation, not a silent relocation.

## T3.2 · `register_project_tools` takes no `kill`, so the composition passes none

The plan's signature is
`register_project_tools(*, store, kill: Callable[[str], None], now)`. The `kill`
injection exists for `delete_project`, which is not registered (T3-1). An
injected dependency with no consumer is a dependency nothing can check, and
building compose's kill lambda now would put the deadlocking wiring one line
away from being used. The parameter arrives with the verb.

`compose.py` carries the reason at the call site, not only here.

## T3.2 · a closed-set enumeration in a third file had to move

`tests/toolsurface/test_compose.py::ALL_TOOL_NAMES` is a literal list of every
tool a composed process registers, and
`test_compose_registers_every_tool_the_daemon_had` asserts equality against it —
so six new names take it red. A `PROJECT_TOOL_NAMES_HERE` group was added and
written out **as literals**, matching that file's stated rule: a list built from
`tools_projects.PROJECT_TOOL_NAMES` would agree with itself no matter which
verbs the composition actually reached. That file is not in T3.2's declared
Files; it is direct breakage caused by this task's one-line change, fixed
inline.

The comment on that group names the missing seventh, so the next reader of the
list does not have to find this document to learn why it is six.

## What T3.2 does **not** prove

- **That a composed process answers all seven.** It answers six. The exit
  criterion is not met, and the phase is *partial* for that reason.
- That anything beyond `list_repos` was **called** through the composed
  registry. The other five are asserted present by name; the one live call is a
  `local_read`, chosen so the test does not park on the real approval deadline.
  Their behaviour is proved in `tests/toolsurface/test_tools_projects.py`,
  behind the shipped authorizer, but in a registry that test composed.
- That the registration sits in the right **order** relative to anything except
  the freeze. `pytest.raises(RegistryFrozen)` after `world.compose()` proves it
  was registered before `freeze_registry()`; that it precedes
  `install_chokepoint` is true by reading and is not asserted.
- That the 105 boundary rules cover the new `toolsurface → signals` edge as an
  *approval*. `tests/boundaries` is green and `test_layer_direction` permits a
  downward import; no rule was added that would notice if that edge later became
  an upward one from a different module.
