## What changed, per BC

- **R2 (`settings.js::choose`).** The click records `autonomy.intent` synchronously; one write is in flight at a
  time; a click during it only moves the intent. When a reply comes back with a level that is not the intent
  (a superseded click), nothing is painted and the intent is sent (`sendIntent` recursion). `state.level` is
  still written only from a confirmed reply (D8's two write sites unchanged).
- **R4 (`projects.js::loadDraftPaths`).** Captures the dialog's project id before the read; drops the answer if
  `draft.project` has since changed.
- **R5 + BC-18 (`projects.js::renderList`, `renderDetail`).** Rows are keyed by project id and kept when their
  signature (`JSON.stringify([project, unique(project)])`) is unchanged; stale rows are removed first, then rows
  are placed moving only out-of-place ones; `aria-current` is updated in place (moved out of `projectRow`), so a
  row click no longer redraws the clicked row. Focus is restored by key when the focused row was redrawn or
  moved. `renderDetail` returns early when `[view.detail, view.status]` is what it last drew.
- **BC-24.** Refused remove: `null` → `view.status` (error + correlation id) in `#p-refusal`; `{removed:false}` →
  `NOT_REMOVED` sentence and a re-read of the dialog's list. Refused/unreachable autonomy change: `write()` fills
  `#settings-note` with `the change was not made: <error> (<correlation_id>)`; a later success clears that
  sentence (only that one). Retried save: `draft.project` (the dialog's baseline) is moved after each
  successful step, so the retry sends only the steps not yet done.

## Deviations

   is the declaration that module's rule asks for.
2. R2's mechanism: the plan says "the last click is re-sent if the server holds an older value". Implemented as
   **one write in flight, the intent sent after a superseded reply** rather than every click posting immediately
   and re-sending afterwards. Both satisfy the plan's invariant; the literal form would make three audited writes
   for R2's two clicks and flip R2's currently passing `logs.two_audit_rows` clause (expected 2) to FAIL. The
   new test pins the two writes (`posts == [{"level": 3}, {"level": 2}]`).

   applied to `renderDetail` as well as the list (same file, needed for the R5 exit criterion).
