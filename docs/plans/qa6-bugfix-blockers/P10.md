## Deviations

- `test_server_short_body.py` sends `Connection: close` on its raw socket. Without it, the client's close
  with the response body unread resets the socket under the server's next `readline`, which prints a
  harmless `ConnectionResetError` traceback from the handler thread.
- Pre-existing noise, not from this phase: `test_routes_m3.py::test_a_terminal_upgrade_from_another_origin_is_refused`
  sometimes prints the same `ConnectionResetError` server-thread traceback (4 in 12 runs on base with src stashed).
  Tests stay green.

## Siblings left open

- `BODY_READ_TIMEOUT_S` is a per-`recv` idle window, not a total deadline (the plan specifies
  `settimeout`). A client trickling one byte every <2 s still holds a thread. A total deadline would need
  a read loop, which is out of scope.
- `int()` accepts `" 10"`, `"+5"`, `"1_0"` and negatives. A negative `limit` reads as empty
  (`read_audit_records` returns `()` for `limit <= 0`). A negative `scrollback` goes to the runner unchanged.
