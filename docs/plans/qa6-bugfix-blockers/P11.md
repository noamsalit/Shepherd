## Decisions and deviations

- `fleetReadable` is true only when **both** fleet reads (`/api/fleet` and `/api/fleet/tree`) answered. The empty state is driven by the tree's workspaces, so if the tree read fails an "empty" fleet is just as unmeasured.
- `FLEET_UNKNOWN` replaces the empty state only when there are no workspaces to show. If a later read fails after cards were drawn, the last-known cards stay on screen, as before. That staleness is BC-03 or U39 territory and is not changed here.
- I added two tests beyond the plan's four:
  - `test_an_answering_empty_fleet_still_shows_the_empty_state` guards F16.
  - `test_an_unchanged_card_keeps_its_node_across_an_event` proves node reuse, not only focus restore.
- The tab walk covers one full cycle ("focus left the document twice"). Chromium keeps its sequential-navigation starting point after `blur()`, so the walk cannot simply start at the top.

## Siblings left open

- The Flock **projects column** (`renderProjects`) still rebuilds with `replaceChildren()`, so focus on a project button is lost on every event. It is the same defect class. The report lists it as "n/a (not driven)", and the plan's Flock half names only the cards.
- `renderEmptyState` still writes `registry: 0` when a readable fleet carries no `discovery.registry_sessions`. That is not reachable from the current payload.
- After `#collapse`, focus is not moved to `#mark` (or back after expanding). It is reachable by Tab, which is what BC-19 asks for.
- The Projects half of BC-18 belongs to P13.
