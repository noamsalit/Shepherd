## Fix

- `STREAM_LIVENESS_S = 0.5`, documented next to `STREAM_POLL_S`.
- `_PipeStream(path, stop, alive)`: on an empty read, every `round(STREAM_LIVENESS_S / STREAM_POLL_S)`
  idle polls (so at most once per `STREAM_LIVENESS_S`, and no clock is read) it asks `alive()`; if false
  it sleeps one poll, reads again until the file is empty (drains the tail), and returns. PP-F: the end
  comes within `STREAM_LIVENESS_S` + one poll after `alive()` turns false.
- `attach()` passes `alive=lambda: self.probe(handle).alive`. That covers both E10 cases: a killed
  pane (no listing row) and a pane that exits by itself (`remain-on-exit` keeps the row, `pane_dead=1`).
- `stop` is `self._run("pipe-pane", "-t", spot)` instead of `_checked`, so unpiping a pane tmux has
  already removed does not raise in the WS handler's `finally`. `_PipeStream.stop` is typed
  `Callable[[], object]` (it was `Callable[[], None]`) so a lambda can be passed, which saves the
  3-line nested def and keeps the file inside its 500-line band.
