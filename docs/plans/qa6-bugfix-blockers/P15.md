## Decisions / deviations

1. **The trimmed snapshot ends with one CR LF.** The plan says the trailing run of LF/CR/space is trimmed, and
   its test says the next live chunk starts at column 0. Trimming alone leaves the cursor at the end of the last
   text line, so a live chunk would start mid-row (U10's `2-live-line.png`). One CR LF is appended after the
   trim (nothing is appended to an all-blank snapshot, which becomes empty). The test asserts both halves.
2. **The parameter is named `capture`, not `bytes`.** `tests/web/test_session_page.py::test_pty_bytes_never_reach_innerHTML`
   treats `bytes` as a pane-byte token and has no allowed shape for a function declaration header, so
   `export function snapshotForEmulator(bytes) {` and `out.push(bytes[i])` were flagged (seen once, during GREEN).
   The scan already allows "handing it to a function" without following into the callee, and this function is a
   pure transform with no sink whose one caller passes its result to `term.write` (which the scan reads). The
   alternative, adding a declaration shape to the scan's `_ALLOWED_PTY_LINE`, would have meant editing a test file
   outside this phase's list; it is not done. No existing assertion was changed.
3. The live-chunk path (`convertEol`, frames 2+) and the server's snapshot bytes are untouched, per the plan's out-of-scope list.
