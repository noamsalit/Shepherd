## Deviations

1. **`result_ending`'s `is_error` rule is narrower than the plan's literal text.** The plan says "when
   `is_error` is true the kind is `error` and the outcome `error`". Taken literally, that breaks two
   existing, undeclared assertions in `tests/master/test_sdk_master.py` (the tape's `result_line`
   sets `is_error = subtype != "success"`):
   - `test_an_unmapped_result_counts_rather_than_raises` pins `error_out_of_cheese` (is_error true)
     to `turn_ended` / `outcome="unknown"` (G-M4-5);
   - `test_a_result_that_ended_badly_is_still_one_turn` pins `error_during_execution` /
     `aborted_tools` (is_error true) to `outcome="error_during_execution"`.
   Implemented instead: an unrecognised subtype keeps the counted `unknown` path; for a known
   subtype, `is_error` yields `("error", "error", unmapped)` when the subtype maps to `turn_ended` or
   the terminal reason is unrecognised, and otherwise leaves the subtype's own error outcome. Both
   plan examples hold verbatim (`("success","api_error",True) == ("error","error",True)`,
   `("success","completed",False) == ("turn_ended","success",False)`), and no existing assertion changed.
   The outcome word is a named constant `ERROR_OUTCOME = "error"` beside `UNKNOWN_OUTCOME`.
2. **The runtime is closed when the open fails after it was built** (one extra test). Building the
   runtime before the drain means a failing drain (or `Thread.start`) would leave a built runtime with
   no turn to close it — directly caused by this phase's reorder, so absorbed.
3. The refusal and error-event texts are the plan's constants verbatim (`OPEN_FAILED_REASON`,
   `TURN_FAILED_TEXT`, both exported in `__all__`).
