# M2 blockers — append only

Per the plan's blocker protocol (§0, K7). Format:

`T<id> · symptom · what was tried · what it blocks · owner: evidence gap | decision gap | host gap | upstream bug`

An **evidence gap** names the probe that closes it — never guess a shape.
A **decision gap** is written *decision · pressure · options · recommendation*,
with the recommendation **not applied**.

## T6-1 · `end_reason` and the two fold marks have no path into `build_stop_evidence` · owner: decision gap

**Symptom.** T4's `mechanical_reason` takes `end_reason`, `auto_compact_pending`
and `quota_notice`. T6's `build_stop_evidence` is handed a `Signal` and a
`SessionSnapshot`, and **none of the three is reachable from either**:

- `normalise.py:85-86` maps the session-ending event to `SESSION_STOPPED` with
  **`fields = {}`** — the reason is not projected, and T10's Files/Surfaces line
  says explicitly that `SIGNAL_FIELD_KEYS` is **unchanged**;
- `SessionSnapshot` gains `auto_compact_at` / `quota_notice_at` only at **T10**,
  which is a different task and (here) a different builder.

**What was tried.** Read `core/signals.py` (`SIGNAL_FIELD_KEYS`, a closed set of
11 — no session-ending key), `engines/claude_code/normalise.py` (Table A — the
session-ending row projects nothing), `core/fold_types.py` (`SessionSnapshot` —
no marks), and the plan's T10 Produces (which adds the marks to
`SessionSnapshot` but adds **no** new `SIGNAL_FIELD_KEYS` member, and says so
twice). There is no route today.

**What it blocks.** Nothing, *yet* — T6 is built and green. But left defaulted
it would silently disable four mechanical rows (`user_exited`, `cleared`,
`logged_out`, `resumed_elsewhere`), the `context_exhausted` bound and
`quota_paused`: a fully tested seam that never runs, which is exactly r3
BLOCKING 2's defect.

**Decision.** Where does the session-ending reason enter the stop lane?

**Pressure.** T10 declares the neutral field set closed and unchanged; K13/K12
forbid `signals/` learning an engine word or reading a computed key; the reason
is an engine value that only the adapter may interpret.

**Options.**
1. Add a neutral `end_reason` key to `SIGNAL_FIELD_KEYS` (12 members) and a
   Table A projection on the session-ending row. Costs: T10's "closed set does
   not need to grow" self-review claim becomes false; benefit: the adapter reads
   its own neutral projection exactly as it already does for `failure_note`, and
   the value never enters `signals/` because only `engines/` interprets it.
2. Give `HookLane`/`handle_stop` the raw payload for stop events. Rejected on
   sight: it puts an engine payload on the `signals/` call path.
3. Thread all three as explicit parameters of `build_stop_evidence`, supplied by
   T11's `handle_stop` from the snapshot (for the marks, once T10 adds them) and
   from a neutral projection (for the reason, which still needs option 1).

**Recommendation (NOT applied).** Option 1 plus option 3: one new
`SIGNAL_FIELD_KEYS` member `end_reason`, one Table A cell, and the three
arguments threaded at T11. The **thread points are already built** — T6 takes
`end_reason`, `auto_compact_pending` and `quota_notice` as **required**
keyword-only arguments, deliberately with no defaults, so `mypy --strict` fails
at any call site that has not decided. The plan's T6 signature is extended by
those three; nothing else deviates. Owner: whoever takes T10 and T11.

## T2-1 · `PRAGMA foreign_keys=off` is a no-op inside the runner's transaction · owner: upstream behaviour, resolved in place

**Symptom.** ADR-M2-4 prescribes the twelve-step rebuild opening with
`PRAGMA foreign_keys=off`. SQLite documents that pragma as a **no-op inside a
transaction**, and `store/migrate.py::_apply` issues `BEGIN` before the first
statement of the migration — so the prescribed statement would have done
nothing, silently, and the `session` table self-references
(`parent_session_id`, `retry_of`) through the drop-and-rename.

**What was tried.** `PRAGMA defer_foreign_keys=ON`, which *is* honoured inside a
transaction and postpones enforcement to `COMMIT` — by which point
`session_new` has been renamed and every reference resolves. It resets itself at
`COMMIT`, so nothing leaks to the next connection. The reason is written into
002's header comment beside the rejected form.

**What it blocks.** Nothing. `test_002_applies_over_001` asserts every column
value, both indexes (by name **and** by behaviour), an empty
`PRAGMA foreign_key_check` and the absence of the scratch table;
`test_002_preserves_column_defaults` covers the defaults a value-only copy would
lose. Recorded because the plan's literal text would have shipped a no-op, and a
future reader comparing plan to code deserves the sentence.

## T18-2a · `doctor` may not name the unsubscribed event · owner: decision gap

**Symptom.** T18-2's honesty debt says `doctor` must render the two refusal
counters as `idle — PostToolBatch is not subscribed (M1 blocker T18-2)`. That
exact string **cannot be written anywhere in `src/` outside
`engines/claude_code/`**: §5.0's engine-vocabulary rule
(`tests/boundaries/test_engine_vocabulary.py`) fails the build on a hook event
name appearing in a string literal, and the plan's own Files/Surfaces line puts
the change in `toolsurface/tools_m1.py` and `cli/`, both of which the rule
scans. The rule was confirmed to bite, not assumed to:

```
$ printf '\nPROBE = "idle — PostToolBatch is not subscribed (M1 blocker T18-2)"\n' \
    >> src/shepherd/cli/commands.py && .venv/bin/pytest tests/boundaries -q
FAILED tests/boundaries/test_engine_vocabulary.py::test_no_engine_vocabulary_in_signals
  "shepherd.cli: 'idle — PostToolBatch is not subscribed (M1 blocker T18-2)'
   names the hook event PostToolBatch"          # line reverted immediately
```

**What was tried.** Four routes, all refused by a rule rather than by taste:
import `SUBSCRIBED_EVENTS` into `cli/` (D19/D35 — an L5 consumer may not import
`engines/`); project it through `tools_m1.py` (same vocabulary rule, and
`tools_m1.py` is another track's file this cycle); derive the name from
`ALL_HOOK_EVENT_NAMES` by index (a magic `[3]`, and the "which event records a
refusal" fact is engine knowledge that lives nowhere as a named constant);
add the constant to `engines/claude_code/events.py` (the task forbids touching
`engines/`, and the plan says that file is **NOT** touched).

**What it blocks.** Only the *name* in the line. What shipped says everything
else: the two counters read `idle`, never `0`, and the reason under them says
the event is not subscribed, that the counters have never been able to move, and
that a `0` would claim coverage this build has never had — with `T18-2` in it.
Evidence: `tests/cli/test_doctor_idle_counters.py` (both required checks).

**Decision.** How does `doctor` come to know which hook events this build
subscribes?

**Pressure.** M1's `doctor` hit this twice already and was right both times
(`ENGINE_UNKNOWN`, `SCHEMA_UNKNOWN`): a datum no tool exposes is a missing
capability, never an import. The engine boundary exists so swapping the engine
never edits `cli/`, and a build that spells an engine event name in the consumer
has swapped that property for one sentence.

**Options.**
1. **A tool reports the subscription.** `hook_subscription_status` in
   `toolsurface/tools_hooks.py` (which already imports `engines/` legally),
   `blast_class=LOCAL_READ`, projecting `{"subscribed": [...], "unsubscribed":
   [...]}`. `doctor` then prints the name it was *handed*, no literal anywhere
   in `cli/`, and the line self-corrects the day the event is subscribed.
2. Name it in `engines/claude_code/events.py` as
   `REFUSAL_EVENT_NOT_SUBSCRIBED` and project that one string. Narrower, and it
   puts the product's deferral into the engine's vocabulary module.
3. Leave it as shipped. Honest, and the name lives in the test and here.

**Recommendation (NOT applied).** Option 1, in the milestone that also owns the
installer (M3/M6 — the same one that can subscribe the event at all). It is a
new registered tool; registering one is a decision this task's surface
(`toolsurface/compose.py`, `daemons/controld.py`, `cli/`'s doctor lines) does
not cover, and inventing it here would have been a second unreviewed capability
in a composition root this task exists to keep thin.

inventing (principle 5 applied to a classifier), and

be quietly widened. But the rate at which heuristic 5 fires on real work is
**unmeasured**, and P-M2-14's `unknown` ceiling does not cover it.

**The probe that closes it.** A session driven to a genuine external wait — a
brief that ends "open the PR and wait for review", captured the way

deploy. Four captures, one vocabulary row each. Until then every
`WAITING_PHRASES` row is `[UNVERIFIED]` in the same sense as the five marked
stop-failure rows.

## T8-2 · heuristic 1 cannot cite its own section without breaking K13 · owner: decision gap

`§TaskCreated / TaskCompleted`. That section heading **is two engine event

**What was tried.** Reading the exclusion's implementation (`_imports.py`,

`"§Hook event names (the enum) — the task-ledger pair, folded"`. That section
exists in `data-schemas.md`, it is where the two events are enumerated, and it
names neither. The **verbatim** citation still exists exactly once, at the fold

position), which is also the only code that reads the events. P-M2-13's test
parses the citation up to ` — ` and checks it against the real headings.

**Decision.** Should the plan's T8 table be amended to this citation, or should
ADR-6's structural exclusion be widened to a second type?

**Pressure.** K1 wants every rule to cite the section its shape came from; K13
wants no engine word in `signals/`. For the two ledger events the two rules

section whose heading is neutral.

**Options.** (a) Amend T8's table to the citation above. (b) Widen
`EVIDENCE_OWNER_CALL` to `{FoldRule, Heuristic}`. (c) Add an alias heading in
`data-schemas.md` (e.g. "the task ledger") and cite that.

**Recommendation (NOT applied beyond the one line already needed to ship).**
(a), with (c) as a follow-up if a reader finds the citation indirect. (b) is
refused: the exclusion's narrowness is the property C6 bought, and a second
owner type doubles the surface a future `class Heuristic` lookalike could use.

## T5-1 · `read_records`' second tuple element is unnamed in the plan · owner: decision gap, resolved in place

**Symptom.** T5's Produces block declares
`read_records(...) -> Iterator[tuple[Mapping[str, object], int]]` and never says
what the `int` is. Three readings are available — a line number, a
`record_version`, or a running skip count — and they are not interchangeable:
a *generic* JSONL reader cannot know about `record_version`, and a skip count
cannot be returned by a generator that has not finished.

**What was tried.** Reading the required checks for a constraint that settles
it: none of the twelve observes the second element.

**Resolved in place.** It is the **1-based line number within the record's own
file** — the only provenance a streaming reader can state, and what a human
chasing one bad line needs. `ReadStats` is then produced by a sibling,
`scan_records`, which is the *same* parser materialised with its bookkeeping
visible: one parse, two views, because a streaming reader cannot return a total
and every caller of a versioned log has to report what it skipped.
`read_stop_records` is the only caller of `scan_records`.

**What it blocks.** Nothing. Recorded because a future reader comparing the plan
to the code will find one more public name in `logs/jsonl.py` than the Produces

## T10-2 · `quota_notice_at` is set by four events and cleared by none · **APPLIED 2026-09-17** (was: decision gap)

**What was tried.** Reading §8 and the plan for a clearing event: there is

quota limit gets a session whose every later stop reads `quota_paused`, and

**Decision.** What clears the quota mark?

**Pressure.** §8 says "a quota notice arrived and **no turn followed**", which

field has been captured.

**removed**, and the golden lane's 33 tests still pass — which is the real proof
the fix reaches the consumer, since that lane is now store-free with no patch
under it.

**Two things worth keeping from how this hid.** First, the same shape as M1's
defect 1: a hand-maintained list mirroring a dataclass, checked by nothing that
knows the dataclass. `store.DELTA_COLUMNS` has a guard
(`test_delta_fields_are_all_known_to_the_store`); the pure lane had none — and
that guard is itself weaker than it reads, asserting only that *one* delta's set

being wrong.**

totality checks passed by vanishing. It now derives cases from the dataclass and

## T12-4 · three T12 remediation decisions taken in place · owner: decision gap, resolved in place

Each of these was forced by a defect the review and the failure hunt found; each
is recorded because a later reader would otherwise have to guess why.

**1. A classifier crash leaves the `unknown` rate's population.** `classify`'s
boundary guard (P-M2-2) turns an unreadable record into `unknown` at confidence
0 with `why = WHY_UNREADABLE`, and `replay` counted that as an ordinary
`unknown`. The unknown rate **is** the tuning backlog (D34, principle 5) and it
decides whether the LLM lane gets built, so a crashed rule entered the backlog
as a rule gap no rule edit can close. Resolved: `ReplayReport.classifier_failures`
counts them, and they are excluded from **both** sides of the rate, which is
therefore measured over the same population before and after — the records the
classifier could read. The diff prints the population beside the rate so the
two numbers can never be read apart. The guard itself is unchanged.

**2. `ToolResult` gained a `Failure` value; `GENERIC_ERROR` did not change.**
`registry.invoke()`'s blanket catch produced the same `ToolResult` for a
capability that is absent and for a handler that raised half way through a
destructive write, so `cli/` told a user whose database had just been rewritten
to *start the shepherd control daemon*. §13's rule is about the error **text**
— a caller may not probe the surface by reading strings — and the text is
unchanged for every mode. What is new is a value consumers branch on
(`UNAVAILABLE` / `REFUSED` / `FAILED`) and a bounded in-process ring that makes
the printed `correlation_id` resolve to something: it was previously formatted
into a string and recorded nowhere, which is an id that should not have been
printed. **M4's audit log (D38) replaces the ring behind `resolve_failure`.**

**3. `--since` is validated at the `replay()` boundary, by `core/clock.parse_date`.**
Nothing validated it at any of the four layers that touch it, so
`shepherd replay --since 30d` — §8's own example — compared `"2026-09-17" < "30d"`,
read zero records, wrote a diff saying so and exited 0. The date reader went
next to `parse_stamp` rather than anywhere else, per the one-clock rule, and
`logs/jsonl._date_fields` was deleted in favour of it. A refusal crosses the
tool seam as `ToolArgumentRefused` and the CLI renders it as `EXIT_USAGE`. An
`unknown-date` partition is now **excluded and counted** when `since` narrows:
it used to be included for every value of `since` (the stem sorts after every
date), so `--apply --since yesterday` could overwrite verdicts derived from
records of any age.

## T19-1 · a hooked `-p` run registers and appears on the fleet page · owner: decision gap, re-framed by the router

**Symptom.** T19 proved live that once the hook is installed, a `claude -p` run
in a throwaway directory registers as `origin=external, ownership=attached` and
appears on `/api/fleet/tree` with a `finished` bucket. M1's
`tests/e2e/test_live_attached_session.py::test_a_p_run_is_not_registered_as_an_attached_session`
still passes — but only because **its** run has no hook installed. The two tests
do not contradict each other; the *name and docstring* of the M1 one claim a
general property it only ever checks in one configuration.

**The builder filed this as "D47 vs E35/RD9/C8". It is not that, and the
correction matters.** D47 governs which *event kinds* may trigger registration
("the first event of **any** kind", not `SessionStart` alone) and exists so a
session that was already open when hooks were installed does not stay invisible.
E35/RD9/C8 governs which *sessions* are fleet sessions, keyed on `entrypoint`.
Those are orthogonal: registering on any event kind and excluding non-interactive
entrypoints can both hold. Nothing in §3 is in tension, so **no decision is being
reversed here** — the hook lane simply does not implement E35.

**Why it does not implement it — measured, not assumed.** `entrypoint` is
**absent from all 429 captured hook payloads** (scanned this session across
`docs/probes/2026-09-14-schemas/hooks/live/*/events.jsonl`; the payload key set is
`session_id`, `transcript_path`, `cwd`, `hook_event_name`, and the per-event
extras). It appears only on **transcript conversation entries**
(data-schemas l.1445: `cli` interactive, `sdk-cli` for `-p`) and in the
**registry** (l.1989). So the discriminator is not reachable from the thing the
hook lane is handed, and the builder's recommended option (b) — "read `entrypoint`
off the frame" — **is not buildable as stated**. That is the finding.

**What it blocks.** Nothing in M2's acceptance: the fleet page is correct about
every session it shows, and a hooked `-p` run genuinely did run. What it costs is
noise — a script that shells out to `claude -p` in a loop would put a finished row
on the page per invocation, and D18's cost model cares about a page a human stops
trusting.

**Decision.** Where does the hook lane learn the entrypoint, if it should?

**Pressure.** The one field that answers it is on neither the payload nor the
`Signal`. K13 forbids `signals/` learning the engine word at all, so any answer is
an adapter projection — the same shape T6-1 established for `end_reason`.

**Options.**
1. **Read it from the transcript.** The payload carries `transcript_path`, and
   every conversation entry carries `entrypoint`. Costs a file open on the
   registration path, which is the hot ingest lane the `hookd` latency probe
   exists to protect (3.4 ms budget), and D24 deliberately keeps evidence off it.
2. **Let discovery reconcile it.** The registry already has `entrypoint` and the
   discovery loop already runs at 2.0 s. The hook lane registers (D47 intact) and
   discovery corrects the row's ownership on its next sweep. Eventually-consistent
   by construction, and it puts the discriminator in the one lane that can already
   see it. Costs a visible flicker for up to one sweep.
3. **Accept it.** A hooked `-p` run is real work and belongs on the page.
4. **Suppress registration for non-interactive entrypoints entirely** — reopens
   exactly the D47 failure mode, for a differently-shaped session. Rejected on
   sight.

**Recommendation (NOT applied).** Option 2, decided **at M3**, which is where
`ownership` stops being a single value and owned sessions arrive. M2 changes no
behaviour for this.

**Applied here, because it is the part that actively misleads:** M1's test is
renamed to say what it checks — an *unhooked* `-p` run is not registered — and its
docstring now names this entry. A test whose name asserts a property it does not
check is the defect class this repo has spent two milestones removing.
