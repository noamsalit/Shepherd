## T25-2 · The audit proof, and why it is not the trap it looks like · **P-M4-4, applied**

T5 said plainly that *"the shipped composition calls this sink"* was not a statement any test on its
file list could make. The trap named in this task's brief is the reason: **an audit test that
injects its own sink proves the collector works, not that the shipped path calls it.**

`tests/toolsurface/test_compose_m4.py::test_the_composed_surface_writes_to_a_real_log` closes it as
follows, and every element is shipped code except the host:

1. the sink is **`plane.audit_sink(store, host)`** — the shipped constructor, over a real
   `RotatingJsonlLog(log_root(host), AUDIT_PREFIX)`, the same resolver `compose.py` uses;
2. the composition is the shipped `compose_tool_surface(...)` call, with the same two arguments
   `controld.py:76` passes;
3. the call is a **real destructive call through `invoke()`** — `kill_session` on the `MASTER`
   audience, which is `_ASK` at level 2, so the gate raises a real card, the worker blocks on
   another thread, the check waits for the card (arrival, bounded at 10 s) and approves it;
4. the record is read back off the disk by **`read_audit_records`**, the single reader, and the file
   that carries it is listed by name.

A second check does the same through the gate's *other* exit (rejected → one `deny` record), because
a log that recorded only what ran cannot answer *"what did it try"*.

**Mutation M2** — the composition installs the gate with `lambda record: None` instead of the sink it
was handed — is red on both, and on nothing else. That is the mutation the plan names.

## T25-3 · The turn id, and the check that proves a release is not a deadline · **RD-T4-2, closed**

§T20-1 and §T21-1 both stopped at the same place: `build_sdk_server(..., turn_id=…)` had a holder
and no producer, and *"a wrong key is worse than an absent one, because it fails silently."*

The shape shipped is the one §T21-1 named, both lines:

```python
# orchestration/master_turn.py
build_master: Callable[[str], MasterRuntime]        # was Callable[[], MasterRuntime]
turn.runtime = self._build_master(turn.turn_id)     # was self._build_master()

# daemons/plane.py
def build_master(store: Store, turn_id: str) -> MasterRuntime:
    return AgentSDKMaster(..., turn_id=lambda: turn_id, ...)
```

The rejected alternative is recorded in `TurnDriver`'s own docstring rather than only here: a
`current_turn_id()` reader answers `str | None`, and every caller then has to invent a string for the
`None` case — the wrong key again, arriving through the repair.

**The check that this is a release and not a deadline** is
`tests/daemons/test_shutdown_master.py::test_the_withdrawal_beats_the_deadline_rather_than_waiting_for_it`.
A turn runs, its runtime makes a real gated call through `toolsurface.client.call` under the turn's
own id, the worker parks in `await_decision`, and the shipped `shut_down` is called. The worker
records `utc_now()` the instant it comes back, and the check asserts that moment is **strictly before
the card's own `deadline_at`** — which a timeout cannot satisfy, because a timeout *is* the deadline.
Every wait is bounded at 10 s against a 600 s deadline, so a mutant that never releases fails at the
bound rather than hanging.

Three mutations hold it down: **M3** (the composition keys the runtime on a plausible-looking literal
instead of the live turn), **M8** (the plane mints its own), **M12** (the driver hands the factory an
empty string). All three red, and M3 and M12 are red on the deadline check specifically.

## T25-5 · `plane.build_master` deviates from the plan's `Produces` in two ways · owner: T25, recorded

The plan pins `def build_master(store: Store, host: HostPlatform) -> MasterRuntime  # reads app_state`.

1. **`turn_id` added.** RD-T4-2, above. The pinned signature was written before the turn-id producer

## T25-7 · Clause 20, and the second withdrawal that is not the first repeated · applied

`daemons/shutdown.py` gained one line at the top of `shut_down` — `withdrawn = close_master(timeout_s)`
— and one counted field on `ShutdownOutcome`. `controld.stop()` is unchanged.

`close_master` does two things, and the second is the one the first revision had no check for:

1. `interrupt_master()` then `wait_for_turn(timeout_s)`. The interrupt withdraws by the turn's id
   **before** it touches the runtime (ADR-M4-3, because P2 measured the interrupt frees nothing), and
   the bounded wait is handed *shutdown's* timeout rather than the driver's 30 s default, so
   `MasterRuntime.close()` has run by the time it returns.
2. a sweep of `withdraw_all(turn_id)` over every card still pending. What is left after step 1 is
   every approval raised by a caller that is **not** the master — §12's rail, a page, the CLI — and a
   worker parked in front of one of those would wait its full 600 s for a process that is one line
   from gone.

The count is returned and printed, because *"shutdown left somebody blocked"* has to be a fact the
exit line can say rather than a silence (principle 5).

`test_shutdown_closes_the_master_and_withdraws` drives the shipped `shut_down` with a turn running and
a card pending, asserted in that order. `test_no_thread_is_left_blocked_on_an_approval` adds a second
blocked caller that is not the master's, asserts the turn's worker thread is **present** before the
shutdown and absent after, and compares the thread sets. **M6** (the step removed) and **M7** (the
step moved below the join and the store close) are both red.

## T25-8 · A real ordering hazard, found by clause 20's second caller · owner: **open, named here** — not fixed inside T25

**Symptom.** A worker released by shutdown's withdrawal has one more thing to do: the authorizer
counts `APPROVAL_WITHDRAWN` against the store (D54). `shut_down` closes the store as soon as the
three threads **it owns** have joined — and a released worker that is not one of those three can lose
that race and come back with `RuntimeError("store is closed")` instead of a refusal. Observed
directly: `tests/daemons/test_shutdown_master.py`'s page-shaped caller hit it on the first run, as an
unhandled thread exception.

**Why it is real and not a test artefact.** `ThreadingHTTPServer` serves each request on a thread
that is not in `Controld.threads`, so in production the same shape is an HTTP request that 500s
during shutdown instead of receiving D54's *"the request this approval belonged to went away"*.

**Why it is not fixed here.** The repair is a decision, not an adjustment: either shutdown waits a
bounded grace for workers it cannot enumerate, or `ApprovalStore` grows a reader for in-flight
waiters (T4's file), or the counter tolerates a closed store — and the third is a silent-failure
swallow this repo refuses. Clause 20 promises nobody is left **blocked**, and nobody is: the release
happens, well inside the deadline, which is what the checks assert.

**What the check does instead of laundering it.** The page's worker records the moment it came back —
before anything else can interfere — and records the outcome it came back with, answer *or* raise.
The assertions are on the release and its timing, and the hazard is named in the test's own docstring
with a pointer here. Recorded rather than made invisible by a `try` nobody reads.
