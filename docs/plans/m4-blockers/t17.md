## T17-2 · The `MasterRuntime` seam has no refusal vocabulary, so `ScriptedMaster` refuses with `RuntimeError` · owner: **decision gap, recommendation NOT applied**

**Decision.** What type does a master raise when it is used after `close()` (DP9's teeth) or asked for
a turn its script does not have?

**Pressure.** `core/runner.py` gives the `Runner` seam `RunnerRefusal`, and `ScriptedRunner` raises it
for exactly this class of thing ("no scripted pane named …"). `core/master.py` has no equivalent. T18's
contract suite has to ask **both** implementations the shutdown question and compare the answers; if
the only shared assertion available is `pytest.raises(RuntimeError)`, the suite passes on almost any
bug that raises — including an `AttributeError` from a half-built `AgentSDKMaster`.

**Options.**
1. `RuntimeError` with a message that names DP9. Zero files outside T17. What shipped.
2. A `MasterRefusal(Exception)` in `core/master.py`, mirroring `RunnerRefusal`. This is the shape the
   repo already uses at the one other seam with a double, and it is what makes T18's assertion bind to
   a *meaning* rather than to a builtin.

**Recommendation, not applied:** option 2, added by **T2's owner or the router**, not by me —
`core/master.py` is T2's file and DP12/§T2-5 pinned its member set with a test. T18 can keep working
against `RuntimeError` today; the message in both refusals is stable and greppable
(`"…is closed; close() releases the runtime…"`, `"…turn(s) and this is send #N…"`).

## T17-3 · `Turn` as the plan specifies it can only script three of ADR-M4-5's seven event kinds · owner: **recorded, NOT applied**

The plan's **Produces** pins `Turn` to two fields, `says` and `calls`. Everything a `ScriptedMaster`
built from it can emit is therefore `text`, `tool_call` and `turn_ended`. The other four kinds in
`MASTER_EVENT_KINDS` — `thinking`, `tool_result`, `rate_limit`, `error` — **cannot be scripted at all**.

Two of those absences are correct and deliberate:

* `tool_result` is §14.2's division of labour — the double says a call was *asked for*, and the suite
  decides what the call did. `test_no_tool_result_is_invented_for_a_scripted_call` pins it.
* `thinking` is cosmetic for a script.

**Two are a real hole, and they are the interesting ones.** `rate_limit` and `error` are the kinds a
chat surface most needs to get right, `error` is ADR-M4-5's "a turn that ended badly and is still a
turn", and **T18's contract suite cannot ask either implementation what happens on one** while the only
double it has cannot produce one. That is §14.2's own argument for `Scripted*` (the cheapest second
caller) failing on exactly the rows where a second caller would pay.

I did **not** widen `Turn`: the field list is in the plan's Produces and widening it is T18's brief or a
router decision, not a quiet edit by the author of the only implementation. **Recommendation for T18:**
add `ends: MasterEventKind = "turn_ended"` (plus an optional payload) to `Turn`, which keeps the
shipped fixtures constructing unchanged and makes the terminal kind scriptable in one field.

## T17-4 · Interrupt semantics: between events, and cleared when the next turn starts · owner: T17, **applied**

§6 says only *"end the turn in flight"*. Three things had to be decided and none is in the plan:

1. **Granularity.** The interrupt is observed **between** emitted events, never mid-event — the same
   granularity a real runtime has, which streams whole blocks. The remaining scripted calls are not
   emitted.
2. **The stream still ends on a terminal event**, with `payload={"interrupted": True}`. A stream that
   just stopped would leave a consumer waiting for a terminal event that never arrives, and the terminal
   event is what `MasterEventKind` calls terminal.
3. **An interrupt with no turn in flight ends nothing** — the flag is cleared at the top of the next
   `send()`. A turn that was never running cannot have been interrupted.

A no-op `interrupt()` was not an option: §14.2 says a `Scripted*` is *"not a stub that returns
`None`"*, and a member that changes nothing is a member a contract suite cannot ask about. MUT-6, MUT-7
and MUT-8 are the three reds that hold this row.

## T17-5 · `billing_mode` has no spelling for "nothing is billed", so the scripted default is `"api"` · owner: recorded, harmless, flagged

§6's `Literal["seat", "api"]` has two members and a script is neither: no seat is consumed and no API
call is made. `"api"` shipped as the closer of the two to "no seat", written into the constant's comment
in those words rather than dressed as a fact. The rest of `SCRIPTED_CAPABILITIES` is honest by
construction — `owns_history=False` (a script's `resume()` restores nothing),
`owns_compaction=False`, `supports_parallel_tool_calls=False`.

**`CURATED_MASTER_FACTS` was deliberately not copied into the default.** Those are measurements of the
*vendor* runtime; a double that claimed them would let a caller pass the contract suite while relying on
a shape only the SDK has — §14.2's D9 argument inverted. A test that needs a different record hands one
to the constructor (`capabilities=` — MUT-15 is the red that proves the constructor value is used).

## T17-6 · The "spawns nothing, reads no clock" check is mutated at the scanner, never by planting an import · owner: T17, applied

The obvious mutation for `test_it_spawns_nothing_and_reads_no_clock` is to add `import time` to
`scripted_master.py` and watch it go red. **I did not do that.** CLAUDE.md (2026-09-17) is categorical:
a planted violation is an inert fixture nothing imports, and `scripted_master.py` is live source the
suite imports and executes. The substitute is stronger, not weaker:

* the scan is a **function over a string**, `forbidden_imports(source)`, not a grep over a path;
* `test_the_scan_bites` drives it with an **inert literal** —
  `"import subprocess as sp\nfrom datetime import UTC\nimport asyncio\n"` — which is text in a test
  module and never an import path, and asserts it finds `{"subprocess", "datetime"}` and not `asyncio`
  (the aliased spelling is the one a `grep subprocess.` misses);
* **MUT-16 neuters the scanner itself** (`return set()`) and the positive control goes red.

So the check has a proof that it can go red without anything importable ever containing the violation.

## T17-10 · Handoffs T17 owes T18 (the contract suite)

1. **The type-level conformance check works today.** `peer: MasterRuntime = ScriptedMaster([])`
   type-checks clean under `mypy --strict` — the `test_hostplatform_contract.py:581` pattern
   (`peer: HostPlatform = scripted_fixture()`) transfers. An `async def send(...) -> AsyncIterator[…]`
   satisfies §6's `def send(...) -> AsyncIterator[…]` structurally; there is no loop thread anywhere in
   this module (DP12). I deliberately did **not** put that annotation in `testkit/` — the conformance

2. **The refusal type is a builtin today** — §T17-2. Assert on the message, or get `MasterRefusal`
   added to `core/master.py` first.
3. **`send()` after the script ends refuses**; it does not repeat the last turn. A suite that drives
   more turns than it scripted will see a `RuntimeError`, by design.
4. **No `tool_result`, no `error`, no `rate_limit` can be scripted** — §T17-3, with the one-field fix.
5. **The observation channel is `sent`, `resumed`, `configured_tools`, `system_prompt`, `interrupts`,
   `closed`.** They are a record the *test* reads; nothing in the double asserts, and no member can fail
   a test by itself (§14.2: not a mock).
