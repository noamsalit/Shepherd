## T27-2 · One public method beyond the plan's Produces block: `TurnDriver.wait_for_turn` · owner: T27, applied, with the alternative recorded

**Decision.** `TurnDriver` ships a sixth verb, `wait_for_turn(timeout_s) -> bool`, which the plan's
Produces block does not list (it names `send_turn`, `interrupt_master`, `close`, `is_running`).

**Pressure.** `send_turn` returns the instant the turn's thread is started; every assertion *about*
the turn — the text that reached the runtime, the kinds that reached the ring, the stamp — is made
after it ends. Without an end-of-turn synchronisation the only way to make those assertions is to
**sleep**, and a sleeping check is the sampling this repo has already been bitten by twice (§T10-7's
survivor, and K20's own failure mode inside the test enforcing K20).

**Options.** (a) sleep in the checks — rejected, it is the failure mode; (b) have `close()` be the
only join, and construct a fresh driver per assertion — rejected, because
`test_the_slot_is_released_when_a_turn_raises` must observe **the same driver** accept a second turn
after the first one failed, which is the whole property; (c) a public `wait_for_turn` (applied).

**Why (c) is not merely a test affordance.** T25's `daemons/shutdown.py` has to end a turn in flight
and know that it ended; `close()` is built on `wait_for_turn` for exactly that reason. The verb
returns `True` only when the turn's `done` Event fired **and** its thread is gone, so "the turn
ended" and "the thread is still unwinding" are distinguishable — which is what
`test_the_driver_starts_no_loop_until_a_turn_runs` compares thread identities across.

**The cost, stated.** It is a **method**, not a module-level callable, so rule 3 of
`tests/orchestration/test_degradation.py`'s enumeration (`inspect.isfunction`) does not see it and it
costs no entry in `POPULATION`. `project_to_stream` does — see §T27-5.

## T27-3 · Flow A step 8 says the driver stamps at the end of a turn; stamping twice loses every stop that happened during it · owner: plan tension, **not satisfied quietly** — one stamp, at turn open

**Symptom.** Two plan sentences pull in different directions.

- Clause 19 and T27's step 2: *"opens a turn with the wake summary when there is one and stamps
  `master_last_turn_at`"* — the stamp is part of **opening**, and `wake.drain` is what moves it.
- Flow A step 8: `the driver stamps and releases -> master_last_turn_at moves`, mapped to
  `test_a_finished_turn_stamps_and_releases_the_slot` — a stamp at the **end**. That test is not in
  T27's Required Checks; step 8 is the only place it appears.

**Why a second stamp is wrong on this tree, and the reasoning is the transferable part.**
`wake.drain`'s own docstring is built around one rule: *"Stamping the instant the read **finished**
would place that stop before the stamp, and it would never wake anything again — a lost stop."* A
turn is minutes long. A session that stops **during** the turn is, at turn-end-stamp time, older than
the stamp — so it is outside the next turn's wake set, permanently. That is the exact failure D31's
component exists to prevent, arrived at from the other end.

**What was tried.** Three readings, and none of them makes a second stamp safe:

1. stamp at turn end with `now()` — loses every stop that landed during the turn;
2. stamp at turn end with the turn's **own** `started_at` — a no-op, because `drain` already wrote
   an instant from the same clock reading; a check asserting "the stamp moved" would be asserting
   nothing;
3. stamp once, at open (**applied**) — `master_last_turn_at` moves on every `send_turn`, is
   observable (`test_a_turn_opens_with_the_wake_summary` asserts it moved to the injected instant and
   that `peek()` is then empty), and a stop during the turn is woken by the next one.

**What it blocks.** Nothing in T27. It is written here rather than resolved in code because Flow A
step 8's own test name belongs to no task's Required Checks, and **whoever writes
`test_a_finished_turn_stamps_and_releases_the_slot` must assert the release, not a second stamp** —
or it will go red against a driver that is correct, and the obvious "fix" reintroduces the lost stop.

## T27-4 · `peek` is in T27's Consumes block and `master_turn.py` does not import it · owner: T27, recorded, deliberate

T27's Consumes names `from shepherd.orchestration.wake import drain, peek, render_wake_text`. The
shipped module imports `drain` and `render_wake_text` only. `drain()` **returns the rows it
consumed** (`WakeSummary.items`), so the opening text is built from the set this turn took; calling
`peek()` first would read the same rows a second time and the import would otherwise be dead code
that `ruff`/review would eventually delete without knowing why it was there.

`peek` is still used — by the **check**, as the arrival assertion:
`test_a_turn_opens_with_the_wake_summary` asserts `peek(store)` names the planted row *before* the
turn and is empty *after* it, which is what makes "the summary was prepended" unsatisfiable by an
empty summary.

## T27-10 · P-M4-21's rule is spelled by attribute name, not by resolved type, and that is wider than the plan's sentence · owner: T27, applied, with the reasoning

**Symptom.** The plan writes P-M4-21 as *"an AST scan over `src/` for calls to `.send(` on a
**`MasterRuntime`-typed name**"*. The shipped rule (`modules_that_call_send` in
`tests/orchestration/test_master_turn.py`) is: any `ast.Call` whose `func` is an `ast.Attribute`
named `send`, anywhere under `src/`.

**Why wider rather than as written.** A type-directed scan is a scan a second driver can escape by
not annotating its variable — and `getattr(runtime, "send")`, or a runtime passed in as `object`, is
invisible to it. The property P-M4-21 protects is *"a second driver improvised into `compose.py` is a
failing build"*, and the narrow rule is exactly the one that improvisation would slip past. **The
cost is stated rather than hidden:** any `.send(` in `src/` is now reported — a socket write, a
generator's `send`, a queue — and the check would go red on one. Measured before the rule was
written: `grep -rn "\.send(" src/ --include=*.py` returned **zero** hits on this tree, so the rule's
blast radius is currently exactly the intended one.

If a legitimate unrelated `.send(` ever lands in `src/`, the fix is an allow-list of
`(module, reason)` pairs in that check — **not** a retreat to the type-directed form.

## T27-11 · No mutation was planted into live source, and what that costs the exception-path proof · owner: T27, recorded so the gap is visible rather than implied

CLAUDE.md's "Mutations" section and T27's brief both forbid planting a violation into live source in
any tree — *inert fixtures only; the red comes from neutering the fixture.* So the release-on-
exception property is **not** proved by deleting the `finally` in `_run_turn` and watching a check go
red. It is proved by three things that are available without planting:

1. **MUT-8** — remove the exception from the arrangement and the check goes red, so the check is
   genuinely driven by a raising turn rather than passing incidentally.
2. **Arrival inside the raising turn.** `test_the_slot_is_released_when_a_turn_raises` waits on an
   `Event` the runtime sets *from inside the loop* and asserts `boom.sent == ["the turn that raises"]`
   before it asserts anything about the slot — so "released" cannot be satisfied by "never taken".
3. **The slot is used again.** The same driver then runs a **second** turn on a second runtime and
   that runtime's `sent` is asserted. A driver that leaked the slot fails at `assert not
   driver.is_running()` and again at `isinstance(..., TurnStarted)`.

**What is still not proved by mutation:** that the release is in a `finally` rather than on some
other path that happens to cover this case. Recorded as the honest residue. The check that would
close it is a mutation of live source, and this repo lost 66 days of uptime to the reasoning that
made one look safe.
