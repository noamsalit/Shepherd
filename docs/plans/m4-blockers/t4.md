## T4-1 · The shape, and the one thing every approval test would otherwise get wrong · owner: T4, **applied**

`ApprovalStore` is a dict of `Approval` plus a dict of `ApprovalOutcome` under **one** lock, with one
`threading.Condition` on that lock (ADR-M4-2). Not a condition per approval: a per-approval condition
is a second lock ordering, and `withdraw_all()` has to hold every one of them at once to sweep a turn
atomically. One condition and `notify_all()` costs a wake-up per waiter and buys an operation that
cannot interleave.

**The compare-and-set is one private method and every terminal transition goes through it.**
`decide()`, `withdraw()`, `withdraw_all()` and the deadline inside `await_decision()` all call
`_resolve()`, which refuses to write over an id that already has an outcome. E-M4-1 (decided twice),
E-M4-2 (withdrawn after approved) and a click racing the deadline are therefore **the same
operation**, not three code paths that agree by inspection.

**The trap the plan names, and how this file answers it.** Every approval assertion here —
a card in `pending()`, an outcome read back, a counter bumped — is *also* true of an
`await_decision` that returns immediately. So the blocking checks assert a **synchronisation**:

```python
def _run(self) -> None:
    self.entered.set()                                     # before the call
    outcome = self._store.await_decision(...)
    self.outcomes.append(outcome)
    self.returned.set()                                    # AFTER it returns
```

and the test asserts, in this order: the card is in `pending()` (arrival); `entered` is set (the
worker really reached the call); `returned` is **not** set within `NOT_YET_S`; `outcomes == []`; the
card is *still* pending; **then** decides; **then** `returned.wait(WAIT_S)` is asserted true. That
is why **MUT-1** (`await_decision` returns immediately) takes **8 of 15** tests red rather than none.
`thread.is_alive()` appears nowhere except as a post-join assertion that the worker finished.

**`await_decision` is a `Condition` with the caller's own deadline and never a poll loop.** The
`while` re-checks the predicate because `wait()` may return spuriously; every pass either returns or
waits the *whole* remaining deadline, so there is no interval anyone chose. `monotonic` is injected —
`tests/boundaries/test_one_clock.py` permits `time.monotonic` explicitly — and that is what makes a
**600 s timeout assert in microseconds**: the fake hands back `0.0` and then `APPROVAL_TIMEOUT_S`, so
the deadline has passed the first time it is consulted and `Condition.wait` is never entered.
`test_an_unanswered_approval_times_out_and_counts` runs in ~2 ms of wall clock for a ten-minute
deadline.

**Withdrawal resolves, it never deletes**, and the difference is asserted from both sides: a withdrawn
id still answers `await_decision` with `withdrawn`, and an id this store never issued raises
`KeyError`. Without the second half, "resolved" and "deleted" are the same observation. **MUT-3**
(delete instead of resolve) is red.

**`turn_id` is `ctx.correlation_id`** — see §T4-2, which is an obligation on three other tasks.

## T4-2 · `withdraw_all(turn_id)` only works if the master threads its **turn id** as `correlation_id`, and nothing in the tree does that yet · owner: **open**, named for T16 / T20 / T27

**Symptom.** `ApprovalStore.create(tool, args, ctx)` is pinned by the plan's *Produces* block and
takes **no** turn id. `Approval.turn_id` is pinned too. The only field of `CallerContext` that can
carry a turn is `correlation_id`, so `create()` reads it there — and `withdraw_all(turn_id)` then
matches on it.

**What is measured on this tree, rather than assumed:**

```text
src/shepherd/orchestration/master_turn.py:182:  turn = _Turn(turn_id=new_ulid(), started_at=self._now())
src/shepherd/orchestration/master_turn.py:214:  self._withdraw(turn.turn_id)
```

T27 (shipped) interrupts by **`turn.turn_id`**, a fresh ULID. The plan's T16 produces
`call(name, args, caller_id, correlation_id)` and its T20 produces
`build_sdk_server(tools, caller_id)` — **with no `correlation_id` parameter at all.** So as the two
signatures stand, the value T20's handler will pass as `correlation_id` is not specified anywhere,
and if it is anything but the turn's id, `withdraw_all()` matches **nothing**, every blocked worker
rides its full 600 s deadline, and ADR-M4-3's release path is dead code with passing tests. That is
the "no caller" register's failure mode (`router-decisions.md`) with the caller present and holding
the wrong key.

**What T4 did.** Documented the derivation in `ApprovalStore.create`'s docstring at the point of use,
and asserted the behaviour rather than the wiring: `test_withdraw_all_resolves_every_pending_approval_of_one_turn`
drives two turns and proves one turn's sweep leaves the other's cards pending (**MUT-4**, `turn_id`
ignored, is red). T4 cannot close it: `client.py` is T16's, `sdk_tools.py` is T20's.

**What it blocks.** ADR-M4-3, acceptance clause 11 and **P-M4-22**. **The closing edit is:** T20's
handler factory takes the turn id and passes it to `client.call(..., correlation_id=turn_id)`, and
T27 keeps interrupting by the same value. Two lines, and they are worth naming now rather than at
acceptance.

**A second, smaller thing about the pinned shape.** `Approval.turn_id` is `str | None`, and
**nothing in this build can produce `None`** — `CallerContext.correlation_id` is a required `str`.
The optional half is unreachable. Recorded rather than "fixed" by narrowing a shape the plan pinned.

## T4-3 · §13's redaction rule now has **two definitions**, and this module cannot import the first · owner: T4 applied a drift guard; the real fix is **open**, owner: router

**Symptom.** T5 landed `toolsurface/audit.py` while this task ran. It declares `SECRET_KEY_MARKERS`
and `REDACTED`, and its own comment says *"this is the first and every later caller imports it rather
than writing its own."* T4's `describe()` is a later caller: the plan requires the card summary to be
*"the tool's own description plus the argument mapping, **redacted**"*.

**Importing it is structurally forbidden, and the reason is already written in this tree.**
`audit.py` imports `shepherd.logs.jsonl` at module scope (line 52). The gate lives **behind
`invoke()`** (T6), and `cli/` imports `toolsurface.registry`. So `approvals.py → audit.py` would make
`shepherd status` load `shepherd.logs` — the transitive hole `types.py`'s own docstring exists to
refuse:

> *"`registry.py` must be able to hold a gate and a sink without importing the modules that build
> them — otherwise importing `registry`, which `web/` and `cli/` both do, drags `shepherd.logs` in
> transitively and DP3's rule is true in the letter it checks and false in the spirit it protects."*

`tests/boundaries/test_l4_import_rules.py` checks **direct** importers, so this would have passed the
shipped rule while defeating it. That is the laundering the rule's own docstring names.

**What was tried, and what shipped.** The two constants are **copied verbatim** from `audit.py` —
same members, same `<redacted>` spelling — and the duplication is made *visible instead of possible*:

```python
def test_the_redaction_rule_has_one_definition_in_the_build() -> None:
    from shepherd.toolsurface import audit
    assert SECRET_KEY_MARKERS == audit.SECRET_KEY_MARKERS
    assert REDACTED == audit.REDACTED
```

A test may import both; `src/` may not. **MUT-20** drops one marker from this module's copy and the
test is red. This is RD-T11-2's cheap rule (*"a scan asserting the literal appears once"*) in the one
form available when the two modules cannot see each other.

**What it blocks.** Nothing today. **Owner: router.** The real fix is one declaration in
`toolsurface/types.py` — stdlib-only, already the home of the shapes both sides share, and the module
whose docstring explains why this is exactly where declarations that both halves need have to live.
It is **T3's file** and neither T4's nor T5's to move, which is why this is recorded rather than
applied. T5 recorded the *adjacent* half as §T5-6 (`tests/signals/test_verdict.py`'s credential-word
ban); this is the other half and they should be decided together.

## T4-6 · Six statements in T4's brief or the plan are false of this tree, and none of them harmfully

1. **"`interrupt()` does not cancel a running tool handler at all"** — true, and load-bearing. §P2's
   capture is what makes `withdraw_all()` the only release path, and it is why
   `test_withdraw_all_resolves_every_pending_approval_of_one_turn` and
   `test_a_withdrawal_denies_the_blocked_call_and_counts` both assert on a **really blocked thread**
   rather than on a return value. No correction; recorded because it is the one input that changed a
   design decision rather than confirming it.
2. **The baseline in the brief is stale, as the brief itself says.** Measured at T4's start:
   `1 failed, 1613 passed, 1 skipped, 47 deselected` — the one failure
   `tests/engines/test_hookd_runtime.py::test_hookd_latency_under_10ms`, which passes in isolation
   (`1 passed in 0.80s`) and is a **load-sensitive latency assertion** on a host running several
   builders' suites. Not T4's, and not reproducible on demand, which is itself the finding: a
   wall-clock threshold in a shared-tree milestone is a test that reports load.
3. **`mypy --strict src` was 118 source files at T4's start and 121 at its end.** T4 adds exactly
   one. The other two are siblings (`toolsurface/audit.py` and one more landing mid-run). §T11-7 and
   §T3-5 said the same thing twice; this is the third confirmation that **a file count is not a
   re-takeable baseline while builders are live** and no exit criterion should be written as one.
4. **`ApprovedBy` has no member meaning "a person declined".** `USER` is *approved by a user*, so a
   rejection ships `approved_by=None` with `reason=DENIED_TEXT`. The pair is unambiguous — `decision`
   is `deny` and the text names the person — but it is a **reading of the enum**, applied here and
   recorded so T5's encoder and T24's card do not each invent a third answer. Reversing it is one row
   in `_ANSWERS` and `test_a_click_is_the_only_thing_that_produces_user_and_the_declared_denial` goes
   red, which is the property that matters: the choice cannot be reversed silently.
5. **`WITHDRAWN_TEXT` is a new literal with no capture behind it.** §11 writes the denial and the
   timeout texts verbatim and says nothing about a withdrawal, because the spec had no state for one
   before D54. It is declared here, once, and it is **BAD-MUT-2**: rewording it survives the suite,
   deliberately — nothing captured pins its spelling, so asserting one would be a shape asserted
   without an example (`data-schemas.md`'s own rule). Named here so the next reader finds the gap
   rather than inferring a contract from a string literal.
6. **"`describe()` … redacted"** is the plan's only mention of redaction at T4, and §13's own
   sentence scopes the pass to `action_log.args` and `work_item.raw` — not to an approval summary.
   Applied anyway, because a card summary reaches the UI *and* the agent's context, which is a wider
   audience than the log. See §T4-3 for what it cost.

**The technique, per RD-T19-7.** Every mutation is a text edit inside **this task's own shadow tree**
(`scratchpad/m4-t4/shadow/`, `src/` *and* `tests/` copied, pytest run with `cwd=` the shadow), applied,
run, and restored in a `finally` with a byte-comparison afterwards. **The live tree was never
mutated, not once, not briefly.** Nothing mutated leaves the process — no signal, no `kill`, no
subprocess verb, no socket (CLAUDE.md's reboot rule); the subject is a pure in-memory store. Driver:
**`scratchpad/m4-t4/t4_mutate.py`**, task-namespaced per RD-T17-11. Every run is bounded at 180 s and
a timeout is reported as `HANG`, never banked as a red — see the note under MUT-14.

**MUT-1 and MUT-16 are the two worth reading, and they are the same lesson from two sides.** MUT-1 is
the plan's own named mutation: an `await_decision` that never blocks. It is red at the *negative*
assertion, which is the whole reason that assertion is written as an Event set **after** the call
rather than as `thread.is_alive()` — T10 shipped a survivor of exactly the latter shape. MUT-16 is
the arrival mutation: with `pending()` answering empty, every emptiness this file asserts
(`store.pending() == ()` after a resolution, `recorder.events == []` for a `HUMAN` call) would be
**vacuously true**, and six tests go red at the arrival above them instead. §T3-4's phrase — *an
arrival nobody has mutated is an arrival nobody has proved* — with three arrivals mutated (MUT-16,
MUT-17, MUT-18) rather than asserted to exist.

**MUT-14 was rewritten because its first form hung rather than failing.** Written as *the audience
check is inverted*, a `HUMAN` call raised a card and
`test_no_human_call_ever_creates_an_approval` blocked forever on a card nobody would answer — the
driver reported `HANG` at 180 s, which is **not a red** and must not be recorded as one. The fix was
to the **test**, not the mutation: it now runs against an already-expired injected clock, so a card
raised by a mutant resolves by deadline and the test *fails*. A mutant whose verdict the suite cannot
deliver is a mutant nobody has proved, and the honest thing was to make the suite able to answer.

**MUT-3's failing line is worth reading too**: deleting the row does not raise anywhere — the waiter
simply never learns, and rides its deadline. It is caught at the *release* assertion, 12 s into the
run, not at an exception. A store that deletes is a store that silently converts every withdrawal
into a 600 s timeout in production.
