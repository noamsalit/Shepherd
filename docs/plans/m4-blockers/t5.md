## T5-1 · The record, written out, with a real example produced by the shipped encoder · **applied**

G-M4-13 says the shipped record is wider than Appendix A's example, so the wide one is

## T5-2 · What T5 proves about the shipped write path, and what it **cannot** prove · owner: **open, T6 + T25**

P-M4-4's trap is that an audit test injecting its own collector proves the collector, not
the composition. T5's answer, and its limit, stated rather than implied:

**Proved.** `test_the_shipped_sink_writes_a_real_log_the_shipped_reader_reads` drives the
shipped `build_audit_sink` over a **real `RotatingJsonlLog`**, whose directory is
`log_root(ScriptedHost(...)) / AUDIT_PREFIX` — the *shipped* path resolver, so the test
cannot agree with a path the composition root would not use. It then asserts the **bytes on
disk** (`data/logs/audit/2026-09-17.jsonl.gz`, listed by name) and reads them back through
the shipped `read_audit_records`. No fixture collects anything. The two stubs in the file
(`_FailingLog`, `_RaisingLog`) exist only for E-M4-6, where a real log cannot be made to
fail twice on demand, and both are named in the module docstring.

**Not proved, and not provable from T5's file list.** *The shipped composition calls this
sink.* `install_chokepoint` is T6's and does not exist in this tree; `compose_tool_surface`
is M1's and composes no chokepoint. P-M4-4's own check —
`test_the_composed_surface_writes_to_a_real_log` — is T25's, and **T5 asserts nothing that
could be mistaken for it**. The gap is named in the test module's docstring so a later
reader does not count T5's integration test as P-M4-4 satisfied.

## T5-3 · "A gate with no audit log" — what T5 can make unrepresentable, and what it cannot · owner: **T6 for the other half**

DP13's mechanism is `install_chokepoint(authorizer, sink)` setting **both or neither**, in
`registry.py` — T6's file, which T5 is forbidden to touch. So T5 built the **same property
one layer down**, where it does own the code:

`build_audit_sink(log, bump, date_of)` has **no defaulted parameter**. An `AuditSink` that
has no log behind it cannot be constructed, there is no lazily-resolved default log (ADR-2
forbids a module resolving its own path, and DP3's rule forbids the import), and
`test_a_sink_without_a_log_is_not_representable` reads the signature and asserts every
parameter's default is `inspect.Parameter.empty`. MUT-16 gives all three parameters
defaults — valid Python, so it is a behavioural mutation and not a syntax error — and it is
red at `assert parameter.default is inspect.Parameter.empty`.

That is the half T5 can build. **Clause 2's self-sealing half remains T6's**: with no gate
there is no decision, "no decision, no record" reads as correct, and only `invoke()`'s
fail-closed rule plus the both-or-neither installer closes it. Recorded here so the router
can see that T5 did not claim to have closed it.

**Three survived the first pass, and two of them were real.** This is the part worth
reading, because an arrival nobody has mutated is an arrival nobody has proved:

* **MUT-12 survived.** The sink's `date_of(...) or UNKNOWN_DATE` was mutated to
  `... or ''` and every test stayed green: the stub log recorded only *how many times* it
  was called, never *which daily file the line was aimed at*. The `unknown-date` behaviour
  was untested. Fixed by recording the date and asserting both directions
  (`[UNKNOWN_DATE]` for an unreadable stamp, `["2026-09-17"]` for a readable one).
* **MUT-15 survived, by coincidence.** Applying `limit` before the sort is a genuine defect
  — a "tail" that returns the *first* `limit` records. It passed because the fixture's
  write order was `middle, newest, oldest`, and slicing that to two and then sorting
  happens to give the same answer. The write order is now `oldest, newest, middle`, chosen
  so **no prefix of the file is the answer**, and the reason is written into the test. This
  is the same shape as M3's ordering assertion satisfied by the query's own `ORDER BY`,
  arrived at from the other side.
* **MUT-19 was a bad mutation, not a survivor.** `return {} or {…}` — `{}` is falsy, so the
  mutation changed nothing. Re-cut as an unreachable `return {}` and red.
* **MUT-16 was a bad mutation on the first pass too**: `log: RotatingJsonlLog | None = None`
  ahead of two non-defaulted parameters is a `SyntaxError`, which is a broken harness and
  not a behavioural red. Re-cut with all three parameters defaulted.
* **MUT-23 and MUT-24 first reported a false RED**: the shadow had no `docs/`, so
  `tests/boundaries` failed at *collection*. Re-run with `docs/` symlinked and with the
  unmutated shadow measured green first (exit 0), which is the only thing that makes the
  subsequent reds mean anything.

## T5-5 · **DP3's rule had a second implementation T7 did not know about, and it blocks any audit writer** · owner: T5, **fixed here; the general question is the router's**

`tests/logs/test_stop_log.py::test_no_read_tool_touches_a_log_path` holds a **second,
independent** AST scan of the same boundary: *no module under `toolsurface/`, `web/` or
`cli/` imports `shepherd.logs`*. T7's widening was deliberately surgical — its docstring
says *"Exactly one function was widened, and it is named so a later builder does not loosen
two"* — and **§T7-2 in the assembled ledger reasoned about exactly this hazard** — *"adding a new
permissive rule in `test_l4_import_rules.py` while leaving the old absolute one in place
would have made T5 red on arrival"* — then named `consumer_violations`/`FORBIDDEN_BELOW_L4`
as the one other path, because *"its `is_consumer` guard excludes L4"*. **That reasoning is
correct about `_imports.py` and false about a third copy T7 never saw**, which walks `toolsurface/` directly and bound the
one module DP3 exists to permit. `audit.py` was red against it the moment it landed.

Widening the copy would have been exactly the second loosening T7 warned about. So the copy
is **deleted**: the import half of that check now calls
`_imports.logs_importer_violations` with `_imports.audit_writer_paths()`, and the
`read_stop_records`/`read_records` **call** half — which has no equivalent there — stays,
unchanged. The delegated half ships with its own arrival assertion (`assert permitted`,
`assert scanned > 5`) and with T7's frozen fixture proving it still bites. MUT-25 is red in
both implementations, which is the check that they are now one rule.

**What is the router's, not T5's:** whether `tests/logs/` should be reaching into
`tests/boundaries/_imports` at all, or whether that check belongs in `tests/boundaries/`
outright. T5 took the smallest change that leaves **one** implementation of DP3's rule. A
count worth having: nothing in this tree asserts that DP3's rule has only one
implementation — T7 asserts it by identity for `test_consumer_boundary.log_reader_violations`
(§T7-2) and had no way to discover a copy living outside `tests/boundaries/`. A property
over `tests/` — *no scan outside `_imports` walks `toolsurface/` for `shepherd.logs`* —
would have caught it, and is the shape that stops a fourth.

## T5-6 · `test_no_llm_lane_exists` forbids the literals `api_key`/`apikey` anywhere in `src/`, which is stricter than the §13 control it guards · owner: **router**

§13 **requires** a *"redaction pass on `action_log.args` … for known secret-shaped keys"*.
`tests/signals/test_verdict.py::test_no_llm_lane_exists` bans the string `api_key` (and
`apikey`) as a literal anywhere under `src/shepherd/`, as part of P-M2-11's *no credential
check exists* property. A redactor that names the key shapes it redacts therefore fails a
rule written to keep an LLM lane from growing — the rule is stricter than the decision it
implements, which is the same shape as §T5-5 and as DP3 itself.

**T5 did not widen it.** `SECRET_KEY_MARKERS` collapses `api_key`, `apikey`, `private_key`
and `access_key` into the single marker `key`, and that is defensible on its own merits —
four spellings of one family is four things to keep in step and the forgotten one is the one
that leaks. It over-matches a key literally named `keyword`, which is the **safe** direction
for a redactor: the cost is a lost field in a log; the cost the other way is a token in a
90-day artefact. MUT-22 proves the family is still caught. The reasoning, including that
this is *not* a dodge, is in the constant's own docstring where the next reader will be.

**The finding stands anyway:** the next person to write a redactor hits this rule, and the
narrow fix (discovery by property, as DP3 does it — the module defining `redact_args`) is a
boundary-rule change T5 will not make on another task's surface.
