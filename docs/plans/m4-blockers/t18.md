## T18-1 · The contract table, and how the second implementation gets added

Ten rows, each a function over the seam's six members and two observation channels, each named for the
question it asks. `test_contract_row` runs every row against every fixture-backed implementation;
`test_contract_row_against_the_engine` runs **the same functions** against the engine runtime and is
`live`-marked, which `addopts` deselects.

| row | the question | observation | who carries it today |
|---|---|---|---|
| `configure_then_send_streams_events` | does the seam do anything at all | the event list moved (arrival) | deterministic |
| `every_kind_is_one_of_ours` | is every `kind` ours (ADR-M4-5) | the emitted set ⊆ the **enumerated** `MASTER_EVENT_KINDS`, after asserting the emitted set is non-empty | deterministic |
| `a_turn_ends_with_exactly_one_terminal_event` | does a turn end, once | count of terminal kinds == 1, and it is the last event | deterministic |
| `a_turn_that_ends_badly_is_still_one_turn` | **what happens on a failed turn** | same invariant, plus the terminal kind is asserted to be `error` | deterministic |
| `interrupt_during_a_turn_stops_it` | does §6's *"end the turn in flight"* mean anything | **arrival first**: `interrupt()` is issued from inside the consuming loop at the first call, which is asserted to have arrived before the second is asserted absent | deterministic |
| `resume_keeps_the_conversation_identity` | does the opaque id reach the runtime and survive a turn | the runtime's **reported** id, `None` → id (arrival) → still id after a turn | deterministic |
| `capabilities_fills_every_field` | is the record complete | `dataclasses.fields()` enumerated; `billing_mode` checked against `get_args()` of the `Literal` the field declares | deterministic |
| `close_then_send_refuses` | DP9's teeth | **arrival first**: a `send()` before `close()` is asserted to work; then `MasterRefusal`, and its `reason` is asserted non-empty | deterministic |
| `close_is_idempotent` | can shutdown call it twice | **arrival first**: the first `close()` is shown to bite before the second is called | deterministic |
| `close_leaves_no_process` | does `close()` release the process | **arrival first**, universal: a turn is streamed before close. An implementation that owns pids gets the stronger arrival (each pid asserted alive, via `/proc`, never a signal); one that declares it spawns nothing has that claim **asserted**, not skipped | deterministic |

**Adding the second implementation is appending one `MasterBuilder` to `MASTER_BUILDERS`.** That
record is `(name, make, skip_reason, live)`; `MASTER_BUILDER_IDS`, the two lane fixtures, the
collection assertion and the skip assertion are all **derived from it** — nothing is restated, which
is D32's three-hand-maintained-lists rule applied to this module.

**The membership is asserted against the tree, not written as a literal.**
`test_every_implementation_of_the_seam_has_a_builder` enumerates every class in `src/shepherd/` that
structurally satisfies `MasterRuntime` (AST: a non-`Protocol` `class` whose method names are a
superset of the seam's, themselves read off `MasterRuntime` at test time) and asserts that set is
contained in the builder names. It goes red the day an implementation lands with no builder (MUT-15),
and red if the scan itself is neutered (MUT-14).

**No count in the module is a literal.** Not the rows, not the builders, not the members, not the
kinds. `test_the_row_table_is_exactly_what_pytest_collects` collects the module in a subprocess and
asserts the node ids as a **set equality** against rows × builders — deliberately unlike
`test_runner_contract.py`'s `CONTRACT_ROWS = 13`, which is a number a human edits every time a row
lands and which is stale in exactly the window where it matters.

## T18-2 · How `ends` was used, and which questions it made askable · RD-T17-3, **applied**

`Turn` gained exactly one field — `ends: MasterEventKind = "turn_ended"`, defaulted, so every
construction in the plan, in §14.2's example and in T17's 17 shipped checks is unchanged (they all
still pass, unedited). `send()` yields `_event(turn.ends, …)` as its terminal event.

**Question 1, now askable of both implementations: what happens on a turn that ended badly.**
`row_a_turn_that_ends_badly_is_still_one_turn` scripts `ends="error"` and asserts the **same**
invariant as the happy row — exactly one terminal event, and it is last — because that sameness is the
contract: a turn that failed is not a different protocol. It additionally asserts the terminal kind
really is `error` (otherwise the row is a second copy of the happy one, which is what MUT-1 turns it
into) and that the `tool_call` before it still arrived: a failure does not retract what already
streamed. Before this field the double could emit `text`, `tool_call` and `turn_ended` and nothing
else, so this row could not have been written at all.

**Question 2: does `TERMINAL_KINDS` mean anything.** `ends` also lets a script end a turn on a kind
that *does not end a turn*. `test_the_terminal_row_goes_red_on_a_turn_that_never_ends` scripts
`ends="rate_limit"` and drives **the shipped row function itself** against it, asserting it raises
`AssertionError`. A control that restated the row's assertions would agree with its own copy; this one
runs the row that ships. It is a check *on* the row, not a contract row, and is labelled as such in
the module.

**What `ends` did not make askable, and this is the honest half:** a `rate_limit` **inside** a turn.
ADR-M4-5 maps `rate_limit_event` to a notification that arrives mid-turn, and one field that names the
*terminal* kind cannot produce a mid-turn event. See §T18-4.

## T18-3 · `MasterRefusal`, and the §T2-5 re-pin · RD-T17-2, **applied**

`core/master.py` gains `MasterRefusal(Exception)` with a `reason` attribute — the same shape as
`RunnerRefusal`, asserted **against `RunnerRefusal` itself** rather than against a restatement of it
(`test_the_refusal_is_the_shape_the_runner_seam_already_uses`). `ScriptedMaster` raises it at both
refusal sites. `row_close_then_send_refuses` asserts on the **type** and on the presence of a reason,
never on the message — a suite that matched a string would agree with whatever spelling the
implementation happened to carry, and `pytest.raises(RuntimeError)` is satisfied by almost any bug a
half-built `AgentSDKMaster` can raise. `AgentSDKMaster` inherits the obligation through that row.

**The base is `Exception`, not `RuntimeError`, deliberately.** Subclassing `RuntimeError` would have
left T17's two existing `pytest.raises(RuntimeError)` assertions green without editing them — which is
precisely the reason not to do it: it keeps alive the spelling this decision exists to retire, and it
would let a runtime raising a plain `RuntimeError` for an unrelated bug pass the shutdown row.

**The re-pin, as required.** §T2-5 pinned `core/master.py` with `test_master_runtime_has_six_members`.
`MasterRefusal` is a module-level name, not a seventh member, so that check does not move — and a pin
that does not move is a pin that did not notice. `tests/test_core_master.py` therefore gains
`test_the_modules_public_names_are_the_pinned_set`: the module's public top-level names, enumerated
off its own AST (the rule — top-level `class`/`def`/assignment, imports excluded as names the module
borrows rather than offers), compared as a **name set** that now contains `MasterRefusal` and nothing
else new. It goes red on the next addition too, which is the point of re-pinning rather than widening.
`test_the_refusal_is_the_shape_…` also asserts `MasterRefusal` is *not* in the Protocol's member set,
so the six-member pin and the name pin cannot drift into disagreement.

## T18-4 · Questions I judged unaskable of both implementations, and therefore did not file as rows

Each of these is a question I wanted and did not put in the table, because a row only one
implementation can answer is a unit test wearing a contract's clothes.

1. **A `rate_limit` arriving mid-turn.** RD-T17-3 named `error` *and* `rate_limit` as the two holes.
   One field closes `error` (the terminal kind) and **does not close `rate_limit`**, which ADR-M4-5
   maps as a notification inside a turn. Closing it needs a second field — an *event sequence* on
   `Turn` rather than a terminal kind — and that is a wider change to a shape the plan pinned than the
   one the router approved. Recorded here rather than absorbed. `rate_limit` is still exercised, as
   the negative control in §T18-2, so the kind is not merely absent from the suite.
2. **`thinking` and `tool_result`.** Correctly absent, per §T17-3 and §14.2's division of labour: the
   double says a call was *asked for* and the suite decides what the call did. A row asserting a
   `tool_result` would be the suite asking itself a question.
3. **"A send past the end of the script refuses."** A property of a *script*, not of the seam —
   `AgentSDKMaster` has no script to run out of — so it is not a contract row. It is T17's
   `test_a_turn_past_the_end_of_the_script_is_refused`, and MUT-3 confirms it is still red there.
4. **"`configure()` mounted what it was handed."** The seam has no member that reports its configured
   tools or prompt, so the only channel is the double's own record, which no real runtime has. The row
   that ships (`configure_then_send_streams_events`) asks the weaker question both can answer. **T19's
   `test_the_prompt_is_frozen_…` and T21 own the stronger one**; if a `configured()` reader is ever
   added to the seam, `test_every_protocol_member_has_a_row` goes red until a row exists (MUT-11).
5. **"`close()` released the connection, not just the process."** No observation channel exists at the
   seam for a connection. `close_leaves_no_process` asks the half that has one.

## T18-5 · The engine lane: skipped, counted, and proved not to be faked

`MASTER_BUILDERS` declares `AgentSDKMaster` **today**, with `engine_skip_reason()` naming
`shepherd.master.sdk_master.AgentSDKMaster` as not importable on this tree. The default run therefore
shows 10 deselected engine cases, and `pytest tests/contracts/test_master_contract.py -m live -rs`
shows `SKIPPED [10] … Task 21 builds it — engine rows are skipped, never faked`.

Two checks, and **neither covers the ground alone**, which is written into the module:

* `test_the_engine_rows_skip_rather_than_fake` runs the live lane in a subprocess with the engine
  forced absent and asserts the skipped node ids **as a set** against builders × rows, plus that the
  reason names the module and the class. Because it forces the absent branch it proves the skip and
  its reason — it cannot see a builder that answers the engine with the double.
* `test_a_skipped_implementation_is_never_answered_by_a_substitute` is that other half, behavioural:
  while the engine is absent, `make_agent_sdk()` **raises**; it does not quietly return a
  `ScriptedMaster`, and its code (docstrings stripped, so the scan does not go red on the prose
  explaining the trap) names no `Scripted` symbol. All four fake-the-engine mutations land here.

**A deviation from the plan's Produces, recorded.** The plan says T21 *extends* `MASTER_BUILDERS`.
Declaring the engine builder now is what gives `test_the_engine_rows_skip_rather_than_fake` something
to assert — a check over an empty engine lane proves nothing, and MUT-21 shows it goes red when the
lane empties. **T21's edit is therefore to fill in `make_agent_sdk()`'s construction site and let
`engine_skip_reason()` return `None`, not to append a record.** No row changes, which is the promise
the plan's wording was making.
