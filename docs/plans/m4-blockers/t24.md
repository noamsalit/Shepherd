## §T24-1 · `/api/autonomy` is a **read** as well as a write — a deviation from the Allowed Scope, declared

T24's Allowed Scope names *"three route-table entries … two read entries
(`/api/approvals`, `/api/audit`)"*. The page ships **three** read entries: the
third is `GET /api/autonomy → get_autonomy_level`.

**Why, and why it is not absorbable as tidiness.** §12 says of the toggle:
*"The autonomy toggle lives here, visible at all times. You should never have to
remember which level you are on."* T24's own Checkpoint Type repeats it as a
manual-checklist item — *"the autonomy toggle shows the current level and
changes it"*. Nothing else on the wire carries the level: `set_autonomy_level`
returns `{level, previous}` and therefore answers only *after* a human has
already changed it, no stream event carries the toggle, and `get_autonomy_level`
is registered with `audiences={HUMAN, MASTER}` but had no route. **The Allowed
Scope as written cannot satisfy the checklist in the same task.**

The alternative considered and rejected: ship the toggle showing an em dash
until the first write. That is honest (principle 5) and it is also a control a
person cannot use — the em dash means *press one of these and find out*, on the
one setting that decides whether an agent needs permission to act.

It is one entry in a path→name map naming a tool the registry already declares,
it adds no import and no handler body, and Gate B's rule is *additive-only with
every addition named in T24* — so it is inside the gate's mechanism and outside
the prose. **Recorded here rather than absorbed**, and pinned three ways: the
closed-set literal in `tests/web/test_routes.py`, Gate B, and MUT-19.

### MUT-15 is a **bad mutation** and is recorded as one

`GAP_NOTE` is the sentence the page shows when the stream reports a gap. Nothing
captured pins its spelling, so asserting it would be *a shape asserted without an
example* (`data-schemas.md`'s own rule) and a gate keyed on one sentence is
defeated by a paraphrase — which is M3's R4, the defect this milestone keeps
re-finding in the checks written to close it. The **structure** is asserted
instead: the page has a gap branch at all, it reaches `say()`, and the gap kind
is `sse.js`'s exported `GAP` rather than a literal this page chose. Same shape,
and same reasoning, as T4's BAD-MUT-2 (`WITHDRAWN_TEXT`).

### MUT-17 was a real hole, and it is the one worth reading

Removing `hidden` from `#chat-view` in `index.html` left **the whole of
`tests/web` green at 143 passed.** `view.hidden = false` is enumerated, so a
*deleted reveal* fails — but a page that was **never hidden** reveals itself
without the script ever running, and every text-level assertion about it still
passes. That is M3's lesson 3 (*"`hidden` in static markup inverts a render
assertion's failure direction"*) arriving **from the other side**: the shipped
enumeration covers the assignment and nothing covered the attribute it assigns
over.

Closed by `test_the_chat_view_ships_hidden_and_the_fleet_ships_visible`, which
asserts both directions — page 1 ships hidden, the fleet ships visible — because
the pair is the degrade: with the module graph broken the browser shows the M1
surface that needs no orchestrator, not an empty conversation frame claiming a
master that never answered. Re-run after the fix: **RED**.

## §T24-4 · `wake_summary` is in T24's `Consumes` and the page cannot call it

T24's `Consumes` block names `wake_summary` among the six tools the page uses.
**The page does not call it and no route was added for it**, deliberately:

* §12's *"while you were away —"* is the master's own opening line. T27's
  `TurnDriver` prepends `render_wake_text()` to the user's text and drains once
  (RD-T16-7a: the driver is the **single** drain site), so the summary reaches
  the page as `master.text` on the stream, which the conversation already
  renders.
* A route would put a second reader in front of it. `wake_summary` calls `peek`
  and does not stamp, so it would not lose a stop — but it would be a second
  surface for one sentence, and the page would then show the summary in two
  places that can disagree.

`wake_summary` is **not** a "no caller" register row: its audience set is
`{HUMAN, MASTER}` and the master reaches it through T20's SDK export. What is
recorded here is that the plan's `Consumes` line overstates what page 1 needs.

## §T24-7 · What this host cannot answer — the human checkpoint

**Checkpoint Type: `human_verify`.** There is no browser, no node and no npm on
this host (G-M3-6, K10). Every claim above is about bytes on disk or bytes on a
socket. **Nothing here says the page renders**, and no test in `tests/web/` may
be read as saying it.

The checklist, verbatim from T24 plus the two items the build added:

1. the conversation streams — a `master_send` opens a turn and the master's
   output appears line by line as `master.*` events arrive;
2. an approval card appears **and both buttons resolve it** — approve releases
   the blocked call, reject denies it, and the card leaves both the sidebar and
   the inline position in the chat;
3. the autonomy toggle **shows the current level** and changes it;
4. the wake summary opens a turn after a session stopped;
5. nothing renders as `[object Object]` or an empty card;
6. *(added)* the nav moves between page 1 and page 2 and the Needs-You rail
   stays put across both — it is the shell, not a page;
7. *(added)* with JavaScript disabled the browser shows the **fleet**, not an
   empty chat frame. This is the degrade MUT-17 exists to protect and it is the
   one item on this list a human can check in two seconds.

Until a human signs this off, T24's deterministic evidence stands and its
rendering claim does not exist.
