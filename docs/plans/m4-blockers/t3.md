## T3-1 · The gate is a **table**, not a chain of `if`s, and that is what makes P-M4-1 provable · owner: T3, **applied**

**Decision.** `decide()` is a lookup into `TABLE: Mapping[tuple[BlastClass, AutonomyLevel, Audience],
Decision]`, whose 24 rows are **written out**. It is not a comprehension and not a branch cascade.

**Pressure.** P-M4-1 requires the totality check to **go red when a member is added to any of the
three enums and no row covers it**. Only one of the three plausible shapes does that:

| shape | what happens when `BlastClass` gains a member |
|---|---|
| a chain of `if`s | the new class falls through to the last branch. `decide` still answers. **Never red.** |
| `TABLE` built by a comprehension over `itertools.product` | `set(TABLE)` grows with the enum, so `set(TABLE) == product` is **tautological** — the test recomputes the expectation the way the code computes it. **Never red.** |
| `TABLE` written out as 24 literal rows (applied) | `set(TABLE)` is a second, independent statement of the domain. The comparison is a real disagreement. **Red.** |

Proved rather than argued: **MUT-1** adds a fifth `BlastClass` member and **MUT-2** a fourth
`Audience` member — both in-process, neither touching a file — and both go red at
`assert set(TABLE) == domain`.

**The cost, stated rather than left to be found.** 24 rows is 24 rows, and the fifth blast class or
third autonomy level the plan defers (§17) costs 8 or 12 new lines. That is the intended price: the
plan calls either one *a Decision pressure, not a task*, and a table makes the next builder pay it in
a failing build rather than in a silent fall-through.

**What it blocks.** Nothing.

## T3-2 · The `HUMAN` row wins over the level-3 row, and the plan's own table is what decides it · owner: T3, **applied, with the rejected reading recorded**

**Symptom.** §11's table has two level columns; DP2 adds a third, `HUMAN`. For
`(local_destructive, LEVEL_3, HUMAN)` two cells claim the same key and they disagree about the
attribution — not about the verdict, which is `allow` either way:

- the **level-3** reading: at level 3 policy auto-approves everything, so the `HUMAN` claim was not
  load-bearing and the honest attribution is `POLICY`;
- the **`HUMAN`-column** reading: the audience is consulted first, and the attribution is
  `CLAIMED_HUMAN` at both levels.

**Applied: the `HUMAN` column, at both levels** — audience above level, blast class above both.

**Why, and the reasoning is the transferable part.** The plan's table is written with **one** `HUMAN`
cell per row, not two, and that cell says *allow, `approved_by="claimed_human"`* without qualifying
it by level. A cell that spans both levels is a cell that spans both levels. The alternative reading
would have the gate's attribution for the same caller flip when somebody moves the autonomy toggle —
so the audit log would say `claimed_human` on Monday and `policy` on Tuesday for the identical call,
and the K23 question *did a person act?* would get two different answers to the same facts. Neither
value overclaims, so this is not a security choice; it is a **stability** choice, and the artefact the
next incident is reconstructed from should not change its account of a call because an unrelated
toggle moved.

**Recorded rather than applied quietly**, because it is a reading of two cells that overlap, and the
next reader deserves to find it here rather than infer it from a dict literal. If T5's encoder or a
later reviewer prefers `POLICY` at level 3, it is **four rows** in `TABLE` and
`test_a_human_destructive_call_is_allowed_and_attributed_as_claimed_human` goes red the moment they
are changed — which is the property that matters: the choice cannot be reversed silently.

**What it blocks.** Nothing. T5 encodes whatever `Decision.approved_by` carries.

## T3-3 · `ApprovedBy.USER` is **unreachable from this module**, and that is asserted rather than assumed · owner: T3, **applied**

K23's whole point is that `claimed_human` and `user` mean different things. The structural half of
keeping them apart is that `decide()` — a pure function of three enum values — **cannot know** whether
a person pressed Approve, so it must never be able to produce `USER`. Written as an assertion over
the table rather than as a docstring promise:

```python
assert ApprovedBy.USER not in {decision.approved_by for decision in TABLE.values()}
```

`USER` is produced in exactly one place, and it is T4's: the compare-and-set that resolves an approval
a person answered. **MUT-5** aliases `CLAIMED_HUMAN` to `"user"` — the collapse K23 names — and goes
red at `assert ApprovedBy.CLAIMED_HUMAN is not ApprovedBy.USER`.

## T3-5 · Two statements in T3's brief are false of this tree, both harmlessly, and both recorded rather than satisfied quietly

1. **"`web/server.py` and `cli/main.py` construct it positionally."** They do not. All three
   construction sites use keyword arguments:

   ```text
   src/shepherd/cli/main.py:164:        ctx=CallerContext(
   src/shepherd/web/server.py:230:        context = CallerContext(
   src/shepherd/web/server.py:299:            CallerContext(
   ```

   Read at `cli/main.py:164-168` and `web/server.py:230-234,299-303`: each passes `audience=`,
   `caller_id=`, `correlation_id=` by name. **The conclusion is unchanged and the reason is
   stronger, not weaker** — a keyword call site is immune to *field reordering* but not to a *required*
   field, which is what `actor_kind` would have been. A required trailing field makes all three sites a
   `TypeError`, all three would have to be edited, and Gate A
   (`test_completing_l4_changed_no_consumer_byte`) compares `(path, sha256)` over `web/` and `cli/` —
   so it goes red on the first edited byte. The defaulted field is what keeps it green, exactly as DP2
   says; only the mechanism in the brief's sentence is wrong.

2. **"mypy `--strict src` baseline 112 files."** True at T3's first measurement and false by its
   last: the final run reports **118 source files**, clean. The six are not T3's — T3 adds exactly
   one source file. `src/shepherd/toolsurface/export.py` (T11), `src/shepherd/master/__init__.py` and
   `src/shepherd/master/prompt.py` (T19) landed while T3 ran, and the file count moves with them. Same
   shape as §T10-9: **a baseline taken while four builders are live is a baseline with other people's
   work in it**, and a builder who treats the number in its own brief as the number on the tree will
   mis-attribute a change.

## T3-8 · T3's mutation ledger — fifteen mutations, fifteen red, none written to any file in any tree

**The technique, because it is the part that transfers.** CLAUDE.md (2026-09-17) forbids planting a
violation into live source in any tree, and T10's answer was to neuter the *fixture* a check is driven
with. A pure table has no fixture: its arrangement **is** live source. So T3's mutations are
**in-process attribute substitutions** — a driver imports `shepherd.toolsurface.policy` and the test
module, rebinds the arrangement (`TABLE`, `AGENT_AUDIENCES`, `ApprovedBy`, `CallerContext`,
`PERMITTED_IMPORTS`, the enum a check enumerates over, the path a scan reads), calls the check
function directly, records the first failing assertion, and restores. **No file in the repo, in a
shadow, or in a scratch copy is edited**, nothing is imported that the suite would later execute, and
the two files the driver does write are inert scratch copies outside the repo that only ever get
`read_text()`-ed and `ast.parse`-d. Driver: **`scratchpad/m4-t3/t3_mutate.py`** (see §T3-11 for why it
is namespaced); each row is `id · what was neutered · verdict · the assertion that caught it`.

| id | arrangement neutered | verdict | the assertion that caught it |
|---|---|---|---|
| MUT-1 | a fifth `BlastClass` member exists, no row covers it | **RED** | `assert set(TABLE) == domain` |
| MUT-2 | a fourth `Audience` member exists, no row covers it | **RED** | `assert set(TABLE) == domain` |
| MUT-3 | the four `external` rows dropped from `TABLE` | **RED** | `assert set(TABLE) == domain` |
| MUT-4 | DP2's `HUMAN` column deleted — a human destructive call falls back to `ask` | **RED** | `assert decide(blast_class, level, Audience.HUMAN) == Decision(…CLAIMED_HUMAN)` |
| MUT-5 | `ApprovedBy.CLAIMED_HUMAN` aliased to `"user"` — the log claims a person acted | **RED** | `assert ApprovedBy.CLAIMED_HUMAN is not ApprovedBy.USER` |
| MUT-6 | the level-2 `ASK` cells fall through to allow | **RED** | `assert decide(blast_class, LEVEL_2, audience) == Decision(ASK, None)` |
| MUT-7 | `AGENT_AUDIENCES` widened to every audience, `HUMAN` included | **RED** | `assert AGENT_AUDIENCES == set(Audience) - {Audience.HUMAN}` |
| MUT-8 | `CallerContext.actor_kind` becomes **required** | **RED** | `assert fields["actor_kind"].default is None` |
| MUT-9 | `CallerContext` never grows the field at all | **RED** | `assert "actor_kind" in fields` |
| MUT-10 | `PERMITTED_IMPORTS` widened to admit `shepherd.core.clock` | **RED** | `assert purity_violations(clock_leak) == ["shepherd.core.clock"]` |
| MUT-11 | the scan reads import **nodes** only, so `importlib.import_module` is invisible | **RED** | `assert purity_violations(call_leak) == ["importlib", "shepherd.toolsurface.registry"]` |
| MUT-12 | the totality assertion replaced by `len(TABLE) == 24` (M3's `== 17`) | **RED** | `assert "len" not in calls` — *"counts where it must compare sets"* |
| MUT-13 | `TOTALITY_CHECK` names a function that does not exist (a rename) | **RED** | `assert set(functions) == set(TOTALITY_CHECK)` |
| MUT-14 | `POLICY_SOURCE` points at a module with no imports | **RED** | `assert seen, "the scan found no imports in policy.py at all"` |
| MUT-15 | `enumerated_domain()` returns the empty set | **RED** | `assert domain` |

**MUT-12 is the one worth reading.** It is M3's `== 17` reproduced deliberately: the totality check
rewritten as a count, against a table that happens to hold exactly 24 rows, so it passes — and
`test_the_totality_check_is_a_set_not_a_length` reads the check's own AST and refuses it. The
meta-check also refuses any comparison against an integer literal inside either half of the totality
check, and asserts the enumeration really is `itertools.product` over `{BlastClass, AutonomyLevel,
Audience}` rather than a hand-written key list that would drift.

**MUT-14 and MUT-15 exist only because the emptiness assertions above them could otherwise be
vacuous** — the same shape as clause 15's subset assertion (T3-4) and clause 6's scope controls. An
arrival check nobody has mutated is an arrival check nobody has proved.

**No survivors and no bad mutations.** Every row changes what its check observes and every one of them
is red at the assertion it was aimed at, verified by capturing the failing line rather than only the
exception type — MUT-1/2/3 could each have gone red at `decide(*key)` raising `KeyError` instead of at
the set comparison, which would have proved a different thing.

## T3-11 · The agent scratch directory is **shared between live builders**, and T3's driver was replaced in it mid-task · owner: T3, **worked around**; the general fix is **open**

**Symptom.** T3 first wrote its mutation driver to the per-session scratch path the harness advertises
as *"session-specific, isolated"*. It is not isolated. A listing taken during T3's run:

```text
t11_mutate.py        t11_export.orig.py    export.orig.py     # T11
prompt.orig.py                                                # T19
t2-mutations.py                                               # T2
mutate.py            policy.full.py                           # T3 (generic name)
```

Four tasks, one directory. By the time T3 went to re-run its driver, `mutate.py` was **T19's**:

```text
$ head -1 <shared>/mutate.py
"""Mutation harness: apply one text edit to prompt.py, run tests/master, restore.
```

**Why this is not merely untidy, and it is the same shape as the incident in `README.md`.** Half the
files in that directory are **restore sources** — `export.orig.py`, `prompt.orig.py`,
`policy.full.py` are the original bytes a builder copies back after a live-source mutation. A driver or
a restore source replaced by a same-named sibling can restore the **wrong file**, or leave a mutation
live in the real tree while its owner believes it was undone, and the failure mode is silent: the
builder's next command is the one that reports the wrong result. This is "append to one shared file"
(README.md, which cost Task 2's and Task 8's entries) with the blast radius moved from prose to
executable code — and it is the M3 `tests/conftest.py` hazard for the third time in two milestones.

**What T3 did.** Re-established everything under **`scratchpad/m4-t3/`**, rewrote the driver there,
and **re-ran all fifteen mutations from the new path**: `rows=15 red=15`, byte-identical verdicts and
identical failing line numbers to the pre-move run. T19's file was left alone rather than deleted —
the whole finding is that a file in that directory may not belong to the task looking at it.

**Restoration is asserted, not assumed.** T3 made exactly **one** deliberate edit to live source meant
to be undone: the slice-2 RED, which shipped §11's table **without DP2's `HUMAN` column** so the
attribution check could fail behaviourally before the column existed. It was restored from
`policy.full.py` — a file which, checked at move time, was still T3's own. The restore is now proved by
a command whose exit code decides, rather than by the suite having gone green:

```text
$ .venv/bin/python scratchpad/m4-t3/t3_verify_restore.py ; echo $?
clean
0
```

It asserts DP2's column present in all four cells, `TABLE` equal to the enumerated product,
`AGENT_AUDIENCES` and `ApprovedBy` not left in a mutated state, `CallerContext.actor_kind` defaulted
rather than required, **no `*.bak` / `*.orig*` / `*.frozen` artefact anywhere under `src/` or
`tests/`**, and T3's fixtures directory holding exactly the two inert fixtures it declared. **No
mutation run of T3's ended without a verified restore**, and none of the fifteen wrote to a tree at
all — they are attribute substitutions restored in a `finally`.

**What it blocks.** Nothing of T3's. **Open for the router:** the per-task rule README.md established
for blocker files has no counterpart for scratch, and three of the four live tasks independently
invented a `t<id>_` prefix while the fourth (T3) did not. The rule that would have prevented this is
the one already written one directory up — *a builder writes to its own path, which nobody else opens*
— applied to `scratchpad/` as well as to `docs/plans/m4-blockers/`. Worth carrying into M5's plan
rather than rediscovering at the next incident.
